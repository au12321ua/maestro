# N-29 细粒度 PAT

状态：已确认 · 优先级：一（N-28 依赖） · 2026-11-03 · 相关：[09](../design/09-identity-security.md)、[02](../design/02-datasets-preparation.md)、U-20、U-27、U-69、[N-28](N-28-datasets-and-evaluation-split.md)

## 问题

PAT 目前只有 read 与 experiment 两类。管理员的 PAT 也只有成员级能力（IAM-02），所有管理员操作都要求网页会话（U-20）。

N-28 让使用者在本地把 benchmark 转换好，再用 SDK 或 Agent 上传。这类自动化需要能上传数据集，甚至能完成准入。按现在的规则，它们只能停下来等管理员打开网页处理。

用户的意见：PAT 应该像 GitHub fine-grained PAT 那样细分权限，由管理员自己决定授予什么，平台不替用户做决策（U-69）。

## 方案

### 有效权限

有效权限 = 账户角色上限 ∩ PAT 勾选的权限 ∩ 对象归属。

- 创建者只能在自己角色的上限内勾选权限。成员的 PAT 最多拿到成员能力；管理员的 PAT 可以勾选管理员权限。
- 角色仍然只有成员和管理员两种，不引入委派，也不引入新角色。
- 撤销 PAT、PAT 到期或账户停用后，从下一次请求起失效；已受理的运行照常继续。这一点不变。

### 权限组（初稿）

| 权限 | 包含 | 角色上限 |
| --- | --- | --- |
| `read` | 读取团队业务数据，发起本人的导出 | 成员 |
| `experiment` | 本人的方案、附件、运行、批次、集合与分析快照 | 成员 |
| `datasets` | 数据集检索与导入（以后包括 N-28 的上传）、首次准备及重试、撤销准入、回收缓存、评分契约；数据集进回收站 | 管理员 |
| `models` | 模型、Harness、模型配置；它们进回收站 | 管理员 |
| `operations` | 团队策略、容量、安装网络，查看部署配置 | 管理员 |
| `override` | 取消、归档他人的运行与对象，把他人的对象放进回收站（管理员对他人对象的覆盖能力） | 管理员 |
| `audit` | 读取审计日志与回收站列表 | 管理员 |

现有的 read 与 experiment 改成两个**预设**，网页创建 PAT 时可以一键选择。按 U-31，现阶段不承诺兼容：现场已有的 PAT 由迁移自动换算成对应的权限组，不需要用户重新创建。

### 始终只能在网页会话中完成（U-69）

即使是管理员的 PAT 也不能做以下操作：

- 创建、查看、撤销 PAT（PAT 不能签发 PAT）；
- 管理成员、邀请和重置密码链接，删除账户；
- 管理主密钥与凭据（模型 API 密钥、Hub token 等），查看模型绑定的凭据；
- 在回收站中物理删除、清空回收站。

另外，任何人都不能读取凭据明文，也不能把模型 API 密钥用作任务的秘密参数（U-28）。这一点不变。

### 带管理员权限的 PAT 的额外限制（U-69）

- 最长有效期比普通 PAT 短：团队策略新增 `pat_admin_max_days`，默认 30 天，不能超过 `pat_max_days`。
- 网页创建时显示醒目的提示；PAT 列表中标出带管理员权限的 PAT。
- 审计日志照常记录创建时勾选的权限，以及每次管理操作的 PAT。

### 实现要点

- `Principal` 把 `pat_scope` 换成权限集合。网页会话按角色得到全部权限，但仍不包含“只限网页会话”的那几类操作；那些操作照旧由 `require_web_session` 守卫。
- 现在的 `require_admin_session` 拆成两种：`require_permission(p, "datasets")` 等按权限组检查的守卫，以及继续保留的“只限网页会话”守卫。`is_admin_session` 用于覆盖他人对象的地方改为检查 `override`。
- 路由层挂的守卫改为声明所需的权限组。逐个路由核对的权限测试改为：每条路由都必须声明所需权限，或者明确标为“只限网页会话”。
- 数据库：`pats.scope` 改为权限列表，用追加迁移完成（U-34）。
- API、SDK 与网页：创建 PAT 时提交权限列表；网页提供预设和勾选框；SDK 的说明里写上各项权限。

### 放弃的做法

- **管理员把管理员权限委派给成员的 PAT**：这等于新增一层角色体系，超出“只有两种角色”的边界。
- **按单个对象授权**（例如只允许操作某个数据集）：首版的粒度到权限组为止，以后有需要再加。
- **上传与准入分成两步，准入只限网页会话**：用户选择把这个决定交给管理员，通过 `datasets` 权限一并授予。

## 影响

- 09：重写第 2、3 节的 PAT 规则与权限矩阵，IAM-02 改为“PAT 的权限受角色上限约束，部分操作只限网页会话”。
- 02 第 1 节、U-20：数据集操作可以由带 `datasets` 权限的 PAT 完成。
- 10：API 与 SDK 中的 PAT 说明。11：网页创建 PAT 的界面。12：团队策略新增 `pat_admin_max_days`。
- 13：权限相关的验收场景。

## 验收

- 成员不能创建带管理员权限的 PAT；带 `datasets` 权限的管理员 PAT 可以导入、准备数据集，但调用模型、凭据和成员管理接口时被拒绝。
- “只限网页会话”的四类操作，用任何 PAT 调用都会被拒绝，且返回统一的错误码。
- 现有的 read 与 experiment PAT 迁移后行为不变。
- 带管理员权限的 PAT 有效期超过 `pat_admin_max_days` 时创建失败。
- 路由权限测试覆盖所有路由，没有遗漏声明。

## 待定问题

1. 权限组的划分是否合适：是否需要把 `read` 再细分，例如只读运行、只读产物？
2. 权限组以后要随 N-28 扩展（例如上传结果包、只评测），扩展时是否需要用户确认？
3. 迁移现有 PAT 是否需要通知持有人。
