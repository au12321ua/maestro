# N-45 自动并发与手动保留运行产物

状态：已确认 · 2026-11-18 · [用户决定 U-109](../design/14-decisions.md)

## 问题

新建运行时，并发上限与每题重复次数并列。重复次数决定收集多少样本，并发只决定最多同时执行多少个试次。现有 Worker 已经逐试次、逐阶段分配资源，新用户仍容易以为提交前得先估算机器能同时跑几题。[运行提交](../design/04-plans-submission.md) · [调度与执行](../design/05-scheduling-execution.md)

另一次反馈来自两周后的复盘。当初测试时忘记归档，回头想看实验经过时，原始产物已经到期。Maestro 仍有配置、分数和产物索引，解释一次异常往往还需要当时的日志、会话、验证报告或输出文件。团队希望能留下选中的实验，同时控制长期占用的磁盘空间。[产物存储与导出](../design/07-artifacts-export.md)

## 自动并发

新建运行默认显示 **“自动并发，本次最多 N 个试次同时执行”**。N 取管理员设置的本次运行有效上限。普通提交沿用团队默认并发，无须用户填写。需要主动放慢的用户可展开“限制本次并发”并调低数字。方案或来源运行带有显式值时，表单展示该值和来源，允许用户区分沿用与改动。

实现上可沿用现有两项策略：省略并发取 `run_default_concurrency`，显式值仍由 `run_max_concurrency` 校验。预检显示解析后的值，受理时写入运行快照。Worker 在这个上限内，继续按就绪试次、主机槽位、阶段资源与提供商名额决定实际并发。运行详情显示实际占用及等待原因。计划试次数仍由任务数与重复次数决定。

## 手动保留产物

建议首版以已结束的运行为操作单位。在运行详情选择 **“保留产物”**，先看到本次可保留的大小、已缺失或过期的项、团队保留空间的已用量与上限。确认后，可用的原始文件在原来的试次和产物链接继续可读，直至解除保留或有权者主动删除。已经回收的文件仍显示原状态。整次操作能把日志、验证证据和交付物一并留下，复盘时无需预先猜中哪份文件有用。

管理员可配置团队字节配额，网页和 SDK 共用保留、查看及解除操作。两个成员同时保留同一运行只计一次；不同运行竞争剩余配额时，以服务端实际可保留字节原子判定。空间不足时给出差额，保留此前选中的运行，由用户决定释放哪份。保留与到期清扫共用一致的状态判定，已进入清理的文件按实际缺失报告。已保留运行在列表中可查到大小，解除前提示哪些文件的普通期限已过，解除后按原到期时间恢复清扫。物理删除按实际释放的内容核减占用。

保留只豁免所选原始文件的自动到期，手动删除仍走原有权限和回收站。运行记录、评分与索引继续按原有规则保存。团队目前可调整普通产物的保留天数（默认 7 天）；是否延长要结合实际回看周期与磁盘增长判断，本次未定新的默认天数或配额数值。长期离线归档可继续用批量导出，连同配置、结果和文件一起带走。

## 实施影响与验收

并发改动集中在新建运行、配置预检和显示。保留功能涉及团队策略、持久化保留状态、到期清扫与删除记账，并需在公开 API、SDK 和网页提供一致的可用状态。实施时据此更新对应的系统说明。

1. 设置团队默认上限，网页不填数字与 SDK 省略并发得到同一个 N。容量不足时实际并发低于 N，能看到等待原因。用户调低上限后按较小值派发，计划试次数一致。已有运行按原配置重跑仍使用快照值并接受现行上限校验。
2. 在独立测试时钟中，保留一条含日志和交付物的已结束运行，让它和普通运行一起越过到期时间。服务重启后，可从原链接打开保留项，普通文件显示过期，两条运行都能查看原评分。
3. 覆盖部分文件已过期、保留与清扫竞争、重复或并发保留、配额不足、解除保留和物理删除。逐项状态、可下载内容与配额一致，失败的保留请求不挤掉其他运行。
