# 08 集合、比较与分析快照

导航：[总览](00-overview.md) · 依赖：[配置](03-configuration-attachments.md)、[提交](04-plans-submission.md)、[评分](06-results-scoring.md) · 相关代码：`src/maestro/domain/comparison.py`（维度、失败分组、对齐与统计）、`src/maestro/services/collections.py`、`src/maestro/api/routes/collections.py`、`frontend/src/components/ComparisonView.tsx`

## 1. 模块职责与需求

最常见的用法是在同一数据集上比较不同的模型与 Harness。平台把几个运行并排放好、按任务对齐、核对除了想比的东西之外是否都一样、把不是被测对象造成的失败排除掉，并能把某一时刻的结论存下来（U-46、U-47）。

| 编号 | 要求 | 现状 |
| --- | --- | --- |
| ANA-01 | 集合只保存运行引用，运行可属于多个集合 | 满足 |
| ANA-02 | 集合可持续增删引用，显示创建者、用途与修改记录 | 满足；团队成员都能增删 |
| ANA-03 | 比较展示哪些条件相同、哪些不同 | 满足；自动检测，不需要声明 |
| ANA-04 | 按任务身份对齐，缺失、失败、重复次数和来源可见 | 满足 |
| ANA-05 | 分析快照固定运行清单、设置和计算输出 | 满足 |
| ANA-06 | 系统提供可计算差异，文字结论由人或 Agent 撰写 | 满足；结论与计算值分开存放 |

四个概念：

- **比较**：任意几个运行（最多 `COMPARISON_MAX_RUNS`）现算的一张表，不保存；网页把设置放在地址里，链接可分享。
- **集合**：团队一起维护的一组运行引用，平台不替用户挑运行。打开集合就是它的比较。
- **集合规格**：建集合时选的场景，规定哪些维度可变、其余维度固定为什么值；只有符合的运行能进来，规格也直接当方案用来提交新运行。
- **快照**：冻结某一刻的比较（运行清单、规格、设置、摆法和算好的整张表），附人或 Agent 写的结论。

比较从不改动运行：剔除、计 0 分、去掉任务都只影响这张表；运行详情页的汇总（[06](06-results-scoring.md) 第 5 节）保持原口径。

## 2. 维度与条件核对

运行快照的比较视图（`comparison_view`，[03](03-configuration-attachments.md) 第 5 节）按维度切开，评分契约（去掉来源字段）单独作为一个维度：

| 维度 | 包括 | 在集合中 |
| --- | --- | --- |
| 数据集 | 数据集内容摘要 | 永远固定 |
| 计分规则 | 指标、单位、方向、阈值、聚合规则 | 永远固定 |
| 模型 | 提供商、协议、地址、模型名、模型参数 | 可选为可变 |
| Harness | 名称、版本、上游版本、内容摘要、参数 | 可选为可变 |
| 附件 | 附件列表（名称与快照内容摘要，标签不参与）、加载顺序、安装时限 | 可选为可变 |
| 资源与时限 | 覆盖的 CPU、内存、Agent 与验证时限 | 可选为可变 |
| 重复次数 | 每任务计划试次 | 可选为可变 |
| 作者参数 | 参数值（秘密参数既不比值，也不比用的是哪个凭据） | 可选为可变 |
| 其他运行设置 | 比较视图里不属于以上的字段（执行方式等） | 永远固定 |

“是否偏离作者基准”由资源覆盖推出，不单独比较。任务范围、并发、运行总时限、凭据和运行身份不进比较视图，因此不是维度。

条件核对逐字段比较各运行，区分缺失字段与显式 null、布尔值与数字，列出相同与不同的维度；可展开查看各运行的完整比较条件。行与列的标题按不同维度的值自动命名（同名不同值时加一段摘要区分）：

- **数据集内容或计分规则不同**：只并排列出各运行自己的原始汇总，不应用比较的失败剔除设置，执行失败不计 0 分；均分、标准差与通过率按各运行全部有效评分试次统计。不对齐任务、不给差值，并说明原因。同名数据集的不同版本内容不同，也属于这一类；不按任务名跨版本对齐，因为同名不等于同内容。
- **其他维度不同**：照常比较。临时比较里，模型、Harness、附件以外的维度不同时给出警告；集合里固定维度不可能不同。
- 另外警告：配置相同的模型实际报告的版本不同、有运行没结束、任务范围不同、指标越低越好（见第 3 节）。

测试模式（Oracle）的运行不能参与比较，也不能加入集合。

## 3. 失败原因分组与计分

没有有效分数的试次按原因归入一个分组。分组比错因（[06](06-results-scoring.md) 第 3 节）细，先看原始异常类型，再看错因，最后看平台的停止原因；分组规则带版本（`GROUPING_VERSION`），写在代码里并记入快照。

| 预设剔除：外部或平台原因 | 预设保留：可能与被测对象有关 |
| --- | --- |
| 模型接口暂时故障：限流、断连、过载、响应停滞 | 运行中内存超限 |
| 认证失败、模型不存在、用量额度或预算耗尽 | 验证器没有产出分数 |
| 镜像构建、环境启动、健康检查、Harness 安装超时 | 附件安装失败或超时 |
| 准备缓存恢复失败、附件原件缺失或传输失败 | 模型接口的其他永久错误（多为请求参数或 Harness 配置） |
| 执行框架不支持 | 未归类的错误 |
| 未开始、取消、中断、服务重启、Runner 无响应、运行总时限停止 | |

用户可以逐组勾选剔除，网页与 SDK 都有“剔除外部原因”的预设（默认）和“不剔除”。规则：

- 被剔除的试次不计入。
- **没剔除的失败算 0 分、未通过**，否则一个总把环境弄崩的 Harness 会显得比实际好。指标越低越好时 0 是最好的成绩，所以这些失败只算未通过，不计入均分，页面给出说明。
- Agent 超时、拒绝任务本来就是有效分数（[06](06-results-scoring.md) 第 3 节），不在剔除范围内。

## 4. 对齐与统计

任务按任务键对齐（数据集内容相同时任务键唯一确定任务）。任务范围有两种：

- **共同任务**（默认）：所有运行都有的任务。剔除后某个任务在某个运行里已没有有效试次（已评分或计 0 分），这一行从**所有运行**一起去掉并计数，保证比的是同一批任务；只剔除了部分重复试次时用剩下的试次。
- **全部任务**：所有涉及的任务，缺的格子显示“未包含”，不给差值。

统计：任务内对有效试次求均值，运行的均分是参与任务的宏平均（与 06 第 5 节一致）；标准差是任务均分的样本标准差；通过率 = 通过试次 / 有效试次。差值只在数据集内容与计分规则相同、且只看共同任务时相对基准运行给出。只给样本量、均值、标准差、通过率与差值；不断言“显著”“提升”，不做置信区间、显著性检验和 pass@k；不假设不同运行的第 1 次重复相互配对。每行另列计划、已评分、计 0 分、剔除与进行中的试次数，各分组的数量，已知用量，以及原始证据现在能否打开。

重跑就是一个独立的运行：加入比较时是单独一行，平台不合并、不挑最高分（U-46，取代 D-008 的合成分析）。用户重跑常常是为了多一组样本；失败不公平的问题由第 3 节的剔除解决。

## 5. 集合与规格

建集合时选场景，场景决定可变维度：

| 场景 | 可变维度 | 默认摆法 |
| --- | --- | --- |
| 比较模型 | 模型 | 排行榜 |
| 比较 Harness | Harness | 排行榜 |
| 模型 × Harness | 模型、Harness | 矩阵 |
| 附件 A/B | 附件 | 排行榜 |
| 重复稳定性 | 无 | 排行榜 |
| 自定义 | 从可选维度中勾选 | 正好两个可变维度时为矩阵 |

固定维度的值从一个已有运行（基准运行），或一份完整的配置请求（新建运行页“把当前表单建成集合”）取得；比较页“建成集合”把检测到的不同维度作为可变维度、第一个运行作为基准。规格保存固定维度的内容值（用来核对），以及从基准得到的请求模板（去掉可变维度的字段和任务选择，用来预填新运行）。

- **加入时核对**：运行的固定维度逐字段与规格比较，“固定”是严格的，任何字段不同（例如同一模型换了中转地址或改了一个参数）都拒绝，并列出哪些字段不同（`COLLECTION_MISMATCH`）。
- **规格不能改**（U-47）：要换比法就“复制并修改规格”，网页在配置表单中预填原集合的固定值，允许修改资源、Harness 等配置和可变维度；符合新规格的运行带过去，不符合的列出原因；原集合与它的快照不变。原来可变、现在要固定的维度必须给出新的基准。
- **团队一起维护**：成员网页会话与 experiment PAT 可以增删任何集合里的运行、改列名、改名称用途和比较设置；每次增删、改名、改设置都记入修改记录（谁、何时、用不用 PAT）。删除集合由创建者或管理员操作，进回收站；物理删除只清空成员列表，快照不受影响。
- **摆法**属于设置，不属于规格：排行榜（每个运行一行，每个可变维度一列，后面是分数列，可排序、选基准）；正好两个维度在变时可用矩阵（行和列各一个维度，格子是均分，同一配置的多次运行在同一格并列显示，不平均）；逐任务表每列一个运行。集合保存摆法、剔除分组、任务范围与基准；只读身份改设置只影响自己这次查看。
- **运行被删**：进回收站的运行在集合里灰显、不参与计算，恢复后回来；物理删除后从集合移除，修改记录写“运行被彻底删除”。

## 6. 从集合提交

运行请求与批次成员可带 `collection_id`（[04](04-plans-submission.md)）：集合模板像方案一样填上请求没给的字段，来源层记为 collection；配置解析把与固定值不符的地方报为阻塞项（`COLLECTION_MISMATCH`），所以“检查配置”时就能发现。受理事务内再核对集合仍在、未满，并把新运行加入集合；不符合时整个请求或整批不受理、不扣额度。带 `resolution_id` 提交时同样核对，并保留解析时的集合字段来源与引用。网页从集合页进入新建运行时，固定维度的输入框已填好并锁住，只选可变维度、任务和并发。

## 7. 快照与结论

快照只从已结束的运行创建（`SNAPSHOT_RUNS_ACTIVE`），保存运行清单（含名称与列名副本）、集合规格（若来自集合）、各运行按维度拆分的完整比较条件、设置、分组规则与比较版本，以及整张计算结果。它之后不再读运行来算数字，所以运行被删、产物过期都不改变它；读取时另查每个运行的原始证据现在能否打开（可查看、已不可用、已删除、已彻底删除），排行榜、矩阵与逐任务表都按当前状态禁用失效链接。表的结构变化时提升 `COMPARISON_VERSION`，读取快照仍须理解旧结构；版本 1 快照未存完整条件，读取时保留其已有结果，不补造条件或重算数字。

结论单独存放：作者、所用 PAT、正文、修改时间；只有作者能改自己的结论，任何能写的身份都能追加。快照由创建者或管理员删除，进回收站；物理删除清空结果与结论，留下回执。

## 8. 已知限制与验收

已知限制：没有跨数据集版本的任务映射；没有显著性检验、置信区间与 pass@k；没有公开发布页面（以后在快照的基础上做）。

验收（13 中的 E2E-OUT-02、E2E-OUT-03）：

- 数据集内容或计分规则不同时不对齐、不给差值并说明原因；其他维度不同时临时比较警告、集合拒绝加入。
- 剔除外部原因后：被剔除的试次不计入，保留的失败按 0 分计入，某任务在某运行没有有效试次时整行去掉并计数；运行详情页的汇总不变。
- 重跑是独立的一行。从集合提交的运行自动加入，规格不符时整批不受理；规格不能修改，复制时只带走符合新规格的运行。
- 新运行加入集合、运行进回收站或被物理删除、产物过期后，快照的清单、规格、摆法与数值不变，证据状态如实显示。
- read PAT 不能改集合、建快照或写结论；网页与 SDK 对同一组运行、同一设置得到同一张表。
