# N-18 网页多语言（中文与英文）

状态：设计中 · 优先级：一 · 2026-10-29 · 相关：[11](../design/11-web-ui.md)、[10](../design/10-api-sdk-cli.md)、[13](../design/13-testing-plan.md)、U-31、U-57

## 问题

U-31 定了网页需要多语言，产品方向包括开源自托管。现在网页的界面文字都直接写在组件里：`frontend/src/` 下约 30 个文件、约 1800 处中文片段（页面越大越多，`NewRunPage`、`AdminPage`、`RunDetailPage`、`DatasetsPage` 各上千行），`index.html` 写死 `lang="zh-CN"`，日期固定按 `zh-CN` 格式化。每加一个界面，以后要抽出的文字就多一批，所以越早做越省事。

后端已经适合多语言，基本不用改：错误返回机器可读的 `code`（约 60 个），`message` 是英文；排队原因、阻塞原因、产物缺失原因等也都是代码，现在由前端 `lib/format.ts` 等处的映射表翻成中文。

## 方案

**一次性抽完，不分批**：所有界面文字移进语言文件，组件里不再出现写死的文字。CI 加一项检查，保证以后的新界面也照此办理。

1. **库**：用 `i18next` + `react-i18next`（MIT，使用最广，支持复数和插值，有 TypeScript 键名检查）。两种语言的文件都打进包里，不按需加载，因为总量只有几百 KB 以内的文字。不选 Lingui：它要在编译期抽取文字，需要额外的构建插件，与 Vite 8 的配合要另外验证。不自己写：复数、插值和类型检查都得重造。
2. **语言文件**：`frontend/src/locales/zh-CN/*.json` 与 `en/*.json`，按页面或模块分文件（如 `common`、`runs`、`datasets`、`admin`）。键名用语义名（如 `runs.cancel.confirm`），不拿中文原文当键，因为改一个字就会变成一个新键。用 TypeScript 声明让写错的键在 `tsc` 时报错。
3. **映射表一并迁移**：`format.ts`、`comparison.ts` 和各页面里按代码翻文字的映射表（`QUEUE_REASON`、`BLOCKER`、`ARTIFACT_REASON` 等）改成按代码查语言文件。
4. **错误**：前端按 `error.code` 显示对应语言的文字。语言文件里没有这个代码时，显示后端的英文 `message`，后面附上代码，与现在一样。`field_errors` 也按同样的办法处理。后端与 SDK 不改，继续返回英文 `message`。
5. **选语言**：第一次打开时按浏览器语言选择，中文环境用中文，其余用英文。侧边栏底部（或设置页）可以切换，选择存在浏览器本地，不存进账户，所以不改接口与数据库。切换时同步更新 `<html lang>`，日期和数字按当前语言用 `Intl` 格式化。
6. **英文初稿由 Agent 翻译**：术语先定一张对照表（运行 run、批次 batch、试次 trial、执行尝试 attempt、准入 admission、集合 collection、快照 snapshot、附件 attachment、方案 plan 等，尽量沿用 API 与 SDK 里已有的英文名），放在 `locales/README.md` 里，以后新增的文字照表翻译。
7. **检查**：加一个脚本（`npm run check:i18n`，进 CI）：
   - 两种语言的键名必须完全一致；
   - `src/` 中语言文件以外的 `.ts` / `.tsx` 不得出现中文字符（注释除外）；
   - 代码里用到的键都必须存在（这一条大部分已由类型检查覆盖）。
8. **测试**：Playwright 冒烟测试固定以中文运行，现有的按文字定位不用改。另加一个英文用例，至少走登录、工作台和新建运行，确认切换生效、页面上没有残留中文。

### 不在本提案内

- **对外文档的英文版**：`docs/` 全是中文、篇幅很大，放到 N-19（外部可安装，下个大版本）时一起做。本次最多补一份英文的根目录 README 摘要，见待定问题。
- **后端日志、`maestroctl` 输出、SDK 的报错文字**：都是英文或面向运维，不翻译。
- **第三种语言**：结构上支持，但不做。

## 影响

- 前端：新增依赖 `i18next`、`react-i18next`（进第三方许可证清单），所有页面和组件改为用 `t()` 取文字；`index.html` 的 `lang` 改为运行时设置。
- 接口、数据库、SDK、Runner：不改。
- CI：`verify.yml` 增加 `npm run check:i18n`。
- 系统说明：[11](../design/11-web-ui.md) 第 1 节写明语言选择与语言文件的位置；[13](../design/13-testing-plan.md) 的冒烟测试补英文用例；交接里的前端检查命令补上 `check:i18n`。
- 以后每个新界面都要同时写中英两份文字，这是长期成本；有 CI 检查兜底，遗漏会在提交时发现。

## 验收

- 切到英文后逐页浏览，所有页面没有中文残留（运行日志、任务名、作者参数等数据本身除外）；切回中文后与现在一致。
- 刷新页面后仍是所选语言；没选过时按浏览器语言选择。
- 已知错误代码按当前语言显示；未知代码显示英文原文和代码。
- `npm run check:i18n`、`lint`、`build`、`check:api` 通过；Playwright 冒烟测试中文全部通过，英文用例通过。

## 待定问题

1. **语言选择存在哪里**：推荐存在浏览器本地（不改接口）；另一种做法是存进账户设置，换浏览器也保留，但需要加接口和迁移。
2. **没选过时的默认语言**：推荐按浏览器语言选择（非中文环境用英文）；另一种做法是固定中文，等对外发布时再改。
3. **英文翻译的审校**：推荐 Agent 翻译后由你抽查几个主要页面，不逐条审；术语对照表请你过目一次。
4. **英文 README**：推荐本次顺带写一份简短的英文 README（项目是什么、如何试用），详细文档留给 N-19；也可以完全留给 N-19。
