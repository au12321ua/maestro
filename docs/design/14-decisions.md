### D-020 本阶段的运行级调度（设计建议，落实 U-05）

- **工作单元暂为运行。** 一个运行由一个 Runner 子进程执行一个 Harbor Job：Job 内 `n_attempts` 取每任务计划试次数，`n_concurrent_trials` 取运行并发。05 第 2～3 节和 15 第 4、6 节中“一个执行尝试对应一个 Harbor 试次”的描述，在本阶段不适用。
- **试次与执行尝试仍是持久记录。** 受理时按任务 × 计划试次数写入 trials；Runner 从 Job 内各试次的目录和结果上报阶段、结果与错因，映射为 execution_attempts。状态、评分、比较和部分重跑都基于这些记录，与将来改为试次粒度后一致。
- **重试。** 本阶段使用 Job 内重试，平台不再叠加外层重试。可否重试由平台错误策略决定（U-15），适配器把它翻译成锁定 Harbor 的 `RetryConfig` 异常名单并显式下发，不依赖 Harbor 默认名单。每次 Harbor 内重试能否识别为独立的 ExecutionAttempt，见 V-12。
- **容量。** 运行按“并发 × 单试次资源”整体预留；提供商并发按各运行的并发之和计算。
- **准备缓存。** 运行启动前确认该运行全部任务的缓存，缺失时加入共享恢复，等待者关联到运行。
- **租约与取消。** 租约和迟到结果防护按运行的 Runner 进程实施；取消粒度为运行，不提供单试次取消。
- **以后的切换。** 改为试次粒度时表结构保持不变，只修改领取规则和 Runner 输入。

## 5. 可配置数值建议

除原稿已经明确的值外，下表均为建议初值，所有限制通过 capability 和管理配置返回实际生效值。其中与机器和磁盘有关的项已在 `config.toml`（U-21，见 [12](12-operations.md) 第 3 节），团队策略类已进数据库并带修订（见“M5 实施记录（第一阶段）”）。

| 项目 | 建议初值 | 说明 |
| --- | --- | --- |
| 计划试次同时执行 | 10 | 原稿规模约束，还受 CPU / 内存限制 |
| 单试次默认资源 | 1000 毫核、2 GiB | 原稿“1 核 2 GB”的标准单位解释需确认 |
| 单运行总时限 | 72 小时 | 包含排队、准备和执行，必须有限 |
| 单运行任务数 | 最大 1000 | 原稿待估计项，需 V-09 校准 |
| 每任务计划试次数 | 1，最大 20 | 总数仍受单运行限制 |
| 单运行计划试次总数 | 最大 10000 | 防止数据库一次展开过大 |
| 单批次运行数 / 计划试次总数 | 最大 100 / 10000 | 任一超限拒绝整批 |
| PAT 默认期限 / 总受理数 | 30 天 / 1000 个运行 | 网页可下调，管理员定义允许上限 |
| 解析结果有效期 | 10 分钟 | 不预留容量，受理需复核 |
| 幂等记录有效期 | 至少 7 天 | 到期后重试可能创建新工作 |
| 自动重试 | 最多 2 次，退避约 5 / 20 秒 | 按锁定 Harbor retry，受停止条件限制，不增加计划样本 |
| Worker 心跳 / suspect | 10 / 30 秒 | suspect 不等于允许立即重派 |
| 取消优雅期 / 清理宽限 | 30 / 120 秒 | 超过后强制停止或报告清理失败 |
| SDK 轮询 | 1～5 秒 | 抖动并遵守 Retry-After |
| 分页 | 默认 50，最大 200 | 稳定游标 |
| 原始产物 TTL | 7 天 | 原稿已定，起算规则为设计建议 |
| 导出 / 暂存 TTL | 24 小时 | 活跃任务与有限 pin 除外 |
| 导出读 pin | 最长 1 小时 | 超时中止，不能无限延迟清理 |
| 单文件 / 单试次原始产物硬上限 | 建议 256 MiB / 1 GiB | 原稿 100 MB 是通常量级，不是硬上限；超限保留明确标记 |
| 单导出包 | 建议最大 10 GiB | 预检估算，实际达到后停止并报告 |
| 附件压缩 / 解包大小、文件数 | 256 MiB / 1 GiB、10000 文件 | 拒绝压缩炸弹和异常展开；已按此实现（M5 第三阶段） |
| 附件安装时限 / 单运行附件数 | 每试次 600 秒，上限 3600 秒 / 8 个 | 团队策略，可在管理页调整 |
| 停止受理水位 | 可用低于 20 GiB 或 15% | 按实际磁盘配置，不可照搬小磁盘 |
| 停止派发水位 | 可用低于 10 GiB 或 8% | 给已有执行收尾留空间 |
| 服务日志保留建议 | 14 天 | 由宿主 journald 策略决定，不影响数据库审计 / 操作记录 |

阶段性 deadline、验证超时及数据集硬资源约束由作者契约和团队策略明确，不统一编造一个适用于所有 bench 的单任务时限。
