# N-48 在开发项目内用 skill 测试 Agent 工具并按专题接手

状态：设计中 · 2026-11-26 · [用户决定 U-113](../design/14-decisions.md)

## 从正在修改的工具出发

开发者已经在自己的仓库里修改供 Agent 调用的命令、脚本或技能，例如调整一个几何检查工具的输出，希望确认被测 Agent 能否读懂并使用它。这里的 harness 指这套外围工具。工具可以通过 Maestro 的普通附件交给试次中的 Agent；实验配置仍可选择 Codex、Claude Code 等现有 Harness。

当前 `maestro-package` 从初始化独立 workspace、在其下维护附件仓库讲起。`maestro-sdk` 在用户已经给出专题链接时会指导接手，常规首次提交示例则直接使用客户端。照着这两个入口走，开发者容易在项目之外再维护一份实验笔记，也容易在第一轮基线与候选都跑过后才想到归入专题。[附件开发 skill](../../skills/maestro-package/SKILL.md) · [SDK skill](../../skills/maestro-sdk/SKILL.md)

## 项目里只装 skill

在两个 skill 的入口及 SDK 安装说明里增加“在已有工具项目中评测”的路径。开发者在原项目启动 Agent，沿用该仓库的开发、构建、提交与交接方式。项目内通常只需 Maestro 的 skill。经常使用独立实验 workspace 的用户仍可选择原有入口。

- **安装与调用。** 示例从项目外的独立 Python 工具环境安装与服务匹配的 SDK，再用这个环境调用 `maestro_sdk.skills.install(项目目录)`。默认会把随 SDK 分发的 skill 写入 `.agents/skills/` 和 `.claude/skills/`，也可指定项目使用的目标目录。示例应让 Agent 知道之后用哪个解释器调用 SDK，升级时用同一环境重装匹配的 skill。正式 SDK 取项目的 GitHub Pages 索引，开发包使用随包 wheel。服务地址与个人 PAT 文件路径由本地环境提供。接入过程无需修改项目依赖、锁文件或初始化 workspace，在非 Python 项目中也适用。[安装器](../../sdk/src/maestro_sdk/skills.py) · [SDK 安装说明](../../sdk/README.md)
- **发布测试对象。** 项目中的 Maestro skill 指导开发者一侧的 Agent 操作平台。给试次安装的是项目实际产出的工具附件。选定提交的所有跟踪文件都属于附件、根目录也有 `manifest.json` 时，可以用 `attachments.publish_commit` 发布该提交。工具只是仓库的一个组件时，按项目现有构建方式，将 `manifest.json`、工具及所需安装文件放入干净的附件目录，核对文件后用 `attachments.publish` 发布。后者发布目录的实际内容。记录源码修订和服务返回的快照 ID，包含未提交改动时注明来源，以快照核对实际测试的内容。[现有发布接口](../../sdk/src/maestro_sdk/resources/attachments.py)
- **验证工具效果。** 从一个最容易观察工具调用的任务开始。可用 Oracle 检查适合该模式的附件安装和参考解；依赖实际 Harness 的安装或发现行为用目标 Harness 验证。在已授权的模型试跑中，从轨迹或产物核对工具是否被发现、调用及产生预期输出。需要判断改动效果时，在相同任务、模型和重复条件下比较基线与候选，并记录评分覆盖和失败情况。[附件实验工作流](../../skills/maestro-package/SKILL.md)

## 从第一次提交开始使用专题

把选择专题放在两个 skill 的普通提交和附件迭代示例前面。专题记录这轮实验要回答的问题，一个仓库可以有多轮不同目的的实验。项目已有说明、任务描述或上次交接都可以提供专题链接，无需再维护一份按仓库映射专题的配置。

| 工作情形 | skill 引导的动作 |
| --- | --- |
| 已给专题链接，或明确要求接续某轮实验 | 打开专题，读目的、最新交接和活动运行，确认已有材料后再决定是否补跑。只给名称时按名称和目的查找；有多个合理候选时请用户指明。 |
| 准备做多轮调试、基线对照或跨人交接，目前没有链接 | 第一次提交前主动找相关专题。已有相同实验目的就复用；没有合适的就建议按这个问题建一个，写明目的并把链接放进项目原有的任务或交接记录。一次性试跑可以直接提交，此后发展成系列时可补入已有运行。 |
| 已选定专题，准备提交或交接 | 示例显式用 `topic.runs.submit`、`topic.runs.rerun` 或 `topic.batches.submit`。用集合比较候选并将集合引用加入专题。交接写本轮判断、支撑它的运行或试次、下一步要查什么；返回专题链接即可接续。 |

实施主要改随 SDK 分发的两个 skill、其参考页和用户安装指引，将已有的专题句柄示例接入常规工作流。这个场景用现有附件发布、专题和集合能力即可完成。工具项目负责产生可测试的内容，Maestro 保存实际受测的快照、运行及比较依据。[专题参考](../../skills/maestro-sdk/references/topics.md) · [附件与配置](../design/03-configuration-attachments.md) · [SDK 与工作区](../design/10-api-sdk-cli.md)

## 验收

1. 给首次接入的 Agent 一个已有工具项目和服务连接方式。它能照指引只安装项目内 skill，用项目外解释器访问 SDK。核对宿主仓库的依赖清单、锁文件和原有开发指引均无改动，未产生另一套 workspace 或实验笔记目录。
2. 用一个仓库子目录里的工具做演练。Agent 能发布只含预期文件的附件并给出对应的源码修订、快照 ID，说明哪项证据验证了安装、哪项表明被测 Agent 实际使用了工具。若只有安装证据，能够如实给出这个结论。
3. 给出“拿这次修改与基线比较，下一轮还会继续”的任务，起初不提供专题链接。Agent 能在首次提交前查找并复用合适专题，或建议创建；所选专题可找到基线、候选、比较集合与交接。换一个没有聊天历史的会话，只给专题链接，也能定位测试版本、结论和待查问题。
4. 用单次试跑和同名专题两种情形检查引导：前者可独立完成，后者能结合目的辨认或向用户澄清。测试演练沿用现有预算授权，收到专题链接本身不会触发付费运行。
