# N-39 skill 补上数据集上传与任务环境

状态：实施中（U-101） · 优先级：建议二 · 2026-11-11 · 相关：[02 数据集与准备](../design/02-datasets-preparation.md)、[03 配置与附件](../design/03-configuration-attachments.md)、[08 集合与比较](../design/08-collections-comparison.md)、[10 API 与 SDK](../design/10-api-sdk-cli.md)、U-69、U-89、U-92

## 问题

mesh2cad 附件实验后登记的想法（`764d601`）指出：两个 skill 都没有解释如何上传数据集、修改任务环境，Agent 因此把改过的环境镜像公开推到了 Docker Hub。平台已有本机构建和保存镜像的能力，缺的是操作者能找到的说明。

以 `dev` 的 `5f72238` 为核对基线：

- `skills/maestro-sdk/SKILL.md` 的描述仍把数据集导入一概称为只能在网页完成，但 `sdk/src/maestro_sdk/resources/catalog.py` 已有 `catalog.upload`，需要带 `datasets` 权限的管理员 PAT。
- `skills/maestro-package/SKILL.md` 讲了附件安装，没有说明什么时候应改任务环境、怎样上传修改后的数据集。
- 环境镜像由平台首次准备时构建或拉取，再存入本机镜像仓库；这些规则已在系统说明 02 第 6 节和 `src/maestro/execution/{materials,preparation}.py` 中实现。

本提案只补齐已有能力的使用指导。下文是建议范围，本轮不修改 skill 或运行行为。

## 方案

### 1. 在 SDK skill 中增加数据集参考页

新增 `skills/maestro-sdk/references/datasets.md`，从 SDK skill 的输入选择步骤和参考目录链接过去，集中写清：

1. 本地目录的根下是各 Harbor task 子目录。平台接受转换好的任务，不在服务器运行 benchmark 转换器。
2. 先通过 `client.me()` 核对当前 PAT；上传需要管理员身份和 `datasets` 权限。权限不足时由管理员上传或提供合适的 PAT，不将扩大权限写成默认步骤。
3. 使用 `client.catalog.upload(directory, namespace=..., name=..., label=..., based_on=...)`。等待导入 Operation，读取其结果中的版本和首次准备 Operation，再等待准备并检查逐任务准入；上传成功不等于所有题都已可提交。
4. 重复内容返回原版本；本次标签和 `based_on` 可能列在 `ignored` 中，不据此声称创建了新版本。
5. 来源说明用挂在数据集版本上的工作流记录写入文字，记上游修订、转换方式及环境修改原因。

示例沿用当前 SDK 的签名和返回模型，不新增上传包装器或另外一套本地状态文件。

### 2. 给出选择任务环境的依据

| 情况 | 建议做法 | 平台如何准备 |
| --- | --- | --- |
| 已有可用镜像 | 任务引用服务主机能拉取的镜像；公开或私有仓库均以主机实际可访问为前提 | 首次拉取并固定 digest，保存到本机仓库 |
| 修改系统依赖或环境文件 | 随任务上传 `environment/Dockerfile` 及构建所需文件 | 平台构建并保存到本机仓库，不需要为此创建公共镜像仓库 |
| Compose 辅助服务需要自建镜像 | 上传对应服务的 `build:` 定义及构建上下文 | 平台准备辅助服务镜像，与主环境一起固定 |
| 为被测 Agent 增加可切换的技能或工具 | 用附件与 `bootstrap.sh`，按附件 A/B 流程实验 | 每个试次安装，不改共享准备缓存 |

本机仓库不会因上传而把镜像发布到 Docker Hub。构建所引用的基础镜像仍须可拉取；私有仓库的认证由部署环境提供，本提案不增加网页镜像凭据管理，也不在任务文件里放仓库密码。

参考页应给出一个最小 Dockerfile 目录示例和一个 Compose 辅助服务的 `build:` 示例，明确下面这些已有边界：

- 主环境用 `environment/Dockerfile` 或任务的 `docker_image`；Compose 的 `main` 不能自行声明 `image:` 或 `build:`。
- 构建上下文和 Dockerfile 必须位于对应环境目录内，不能依赖上传目录外的文件。
- `image:`、`build:` 中的变量按默认值固定；无默认值或名称像秘密的变量不能准备，不能靠运行参数改变镜像。
- 说明系统说明 02 第 6 节已有的构建选项限制，以及宿主 bind、Docker socket 等不支持的写法。skill 内写清规则本身，不引用内部文档章节或 U / N 编号。

### 3. 说明版本与比较的后果

- 改环境文件就是改任务内容，上传后得到内容不同的新版本。文件可执行位也参与内容身份。
- 上传来源的数据集可以继续上传版本；`based_on` 只能指向同一上传数据集内未删除的版本，只记来源关系。
- Hub 数据集只能从 Hub 得到版本。要改 Hub 任务，应在本地取得并转换所需材料，以新名称上传为另一数据集，不能向 Hub 名称上传，也不能跨数据集填 `based_on`。
- 数据集内容不同的运行，比较只并列原始汇总，不跨版本按题名对齐或给差值。跨版本沿用读取汇总与留出标记的规则不代表比较支持跨版本对齐。

### 4. 两个 skill 的入口保持一致

修正 `maestro-sdk` 的描述：成员、凭据、模型等管理仍指向网页；明确数据集上传已有 SDK 入口及管理员 PAT 要求。`maestro-package` 在选择附件内容和改进假设处链接数据集参考页，提醒修改任务环境会改变实验条件，不能把它当作只改附件的候选。

工作区模板若重复了旧的限制，同步修正；示例和限制集中放在数据集参考页，两个 skill 不各写一份。

## 影响

- 修改范围是 `skills/maestro-sdk/`、`skills/maestro-package/`，以及确有旧说法的 SDK 工作区模板；随 SDK 发布。
- 实施时核对 [10](../design/10-api-sdk-cli.md) 的 skill 导航说明。数据集、准备、比较的系统行为已存在，不为本提案另增规则。
- 不新增接口、数据库字段、部署配置或镜像推送流程。

## 验收

- 从两个 skill 都能找到数据集上传与改环境的指导；不再出现“数据集导入一律只能在网页”的表述。
- 示例调用与当前 SDK 签名、Operation 结果一致；说明上传权限、首次准备、重复内容及 `based_on` 的归属限制。
- 一个“给主环境增加依赖”的例子能指向上传 Dockerfile，由平台构建保存；没有必须公开推镜像的步骤。
- 明确 Hub 变体须另建上传数据集，以及改环境后的比较限制。
- 执行文档链接检查和 SDK / skill 安装、发布内容的相关测试，确认新增参考页随包安装且链接可读。本项验证不需要真实模型请求。
