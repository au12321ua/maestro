# 11 网页信息架构与交互

导航：[总览](00-overview.md) · 依赖：[配置](03-configuration-attachments.md)、[API](10-api-sdk-cli.md)、[权限](09-identity-security.md) · 相关代码：`frontend/src/`（`App.tsx` 路由与导航，`pages/` 各页）

## 1. 页面结构

Vite + React + TypeScript + shadcn/ui（Radix）+ Tailwind，工程在 `frontend/`，构建到 `src/maestro/static/` 由同一 HTTP 服务托管，生产主机无需 Node。请求类型由 `openapi/maestro-v1.json` 生成，页面只调用公开 API（[10](10-api-sdk-cli.md)）。未登录时依次是初始化管理员、登录、邀请接受（`/invite`）页。

登录后左侧是侧边栏：工作台；实验（运行、批次、集合、方案）；资源（数据集、附件、导出）；设置；管理员另有“管理”，进入管理页时在其下展开各分区。“新建运行”是运行列表与工作台上的按钮，不在侧边栏。侧边栏底部是系统可受理状态、当前用户与退出；宽屏上可收起成只有图标的窄条（收起与否存在浏览器本地），窄屏上是从左上角打开的抽屉。不可受理时内容区顶部的横幅说明原因，已有记录仍可查看（U-45）。

| 路由 | 主要内容与操作 |
| --- | --- |
| `/` 工作台 | 我的近期运行、团队近期结果、待处理事项（第 6 节）、系统状态 |
| `/runs` | 运行列表：全部 / 我的、受理日期范围、分页；多选后比较或导出 |
| `/runs/new` | 新建运行与批次草稿（第 2 节）；`?from=<run>` 为修改后运行，`?collection=<id>` 从集合新建 |
| `/runs/:id` | 运行详情（第 3 节） |
| `/batches`、`/batches/:id` | 批次列表、成员运行进度、取消批次、比较这一批 |
| `/compare?runs=…` | 临时比较（第 8 节）；设置放在地址里，可分享；可建成集合或保存快照 |
| `/collections`、`/collections/:id` | 集合列表与新建、全部快照；集合页：规格、比较、运行（列名、移出）、快照、修改记录，从集合新建运行，加入已有运行，复制并修改规格 |
| `/snapshots/:id` | 冻结的比较、证据现状、结论 |
| `/datasets` | 数据集与版本、任务表（准入 / 内容 / 缓存 / 可提交分列）、作者参数、评分契约；管理员在此添加（检索 Hub）、首次准备、撤销准入、回收缓存、删除 |
| `/plans` | 团队方案：创建者编辑（JSON 模板，带修订检查）、复制、归档、用它新建运行 |
| `/attachments` | 已发布附件：发布新版本、启停、删除 |
| `/exports` | 本人导出的进度、缺失与警告、到期与下载 |
| `/settings` | 账户信息、修改密码、PAT 创建 / 撤销 / 删除、SDK 快速上手 |
| `/admin/<分区>` | 每个分区有独立地址，从侧边栏进入：成员与邀请、凭据与主密钥、模型、Harness、团队策略、容量、安装网络（含只读的部署配置）、数据集导入、回收站、审计、维护 |

非管理员访问 `/admin` 被重定向到工作台；服务端仍独立校验权限。

排版规则（U-45）：

- 长内容不撑宽页面：网格的格子默认可以收窄到比内容窄（`index.css` 的全局规则），flex 行里放长文本的格子加 `min-w-0`；日志与代码块在自己的框里横向滚动，长路径在表格里任意处换行。网页冒烟测试用超长任务名和几千字符的日志行，在桌面与手机宽度下检查页面没有横向滚动条。
- 长名字（任务键、运行名、批次名、产物路径）单行截断，悬停显示全名；任务键旁可复制。同一列表的任务键有共同前缀时省略中间，保留开头与能区分彼此的结尾（例如 `swebench…-11099`）。只出现一次的名字（试次标题、运行标题）完整显示，可在任意处换行。
- 管理页与设置页的表单（`SettingsForm`）每个字段一行：桌面上标签一列、输入框一列，说明与错误在输入框下方，按钮与输入框左对齐；窄屏上下排列。筛选栏、数据集检索这类短表单仍按行内排列。

管理页“Harness”发布容器内的 Harness 时须填上游版本，表单下方列出上游标签、最近正式版本、Maestro 测过的版本与团队已发布的版本，可一键填入（[03](03-configuration-attachments.md) 第 2 节）；版本列表标出上游已有的更新版本。

已知限制：运行列表只提供“我的”与日期筛选，API 支持的按数据集、模型、Harness、附件、状态筛选没有界面；方案没有修订历史视图；数据集版本没有独立地址；维护分区只读（健康、可受理、执行进程、执行器、主密钥、数据库结构），更新、备份与恢复在主机上执行（[12](12-operations.md)）。

## 2. 新建运行流程

一页完成：可选方案（并可把当前表单另存为方案）→ 名称与数据集版本 → 执行方式（模型实验或 Oracle）→ 模型与 Harness（只能选择管理员维护的配置，Harness 按模型协议过滤）→ 附件（可调整加载顺序）→ 规模与资源 → 作者参数（秘密参数只能选通用凭据的名称）→ 任务选择 → “检查配置”。

- 检查调用配置解析，确认区显示每项生效值与来源、blockers 与警告；改动表单后需重新检查，再“按此配置提交运行”。
- 提交持有一个幂等键，结果未知（断线、超时）时保留该键，“重试提交”不会重复受理；只有明确完成后才换新键。按钮防重复点击只是交互，一致性靠服务端幂等。
- 任务表分列显示准入、内容可得性、本机缓存与可提交；已准入的冷缓存任务可勾选，运行时自动恢复。不可提交的任务禁选并显示原因。
- 从集合新建（`?collection=`）时，集合的固定维度已填好并锁住（数据集、执行方式，以及固定的模型、Harness、资源与重复次数），提交带上集合；与集合不符的地方在“检查配置”时作为阻塞项列出。实验方案卡片里可以“把当前表单建成集合”，固定维度取表单当前的值。
- “加入批次草稿”把当前配置放入草稿，可预览整批展开、试次数与逐项阻塞；整批通过才受理，任一项不能提交则整批不受理、不扣额度。修改后运行单独提交，不进批次。

## 3. 运行详情布局

- **顶部操作**：刷新、导出、重跑（全部任务 / 只重跑有未得分试次的任务，均创建新运行）、修改后运行、加入集合、删除（已结束）、取消；按钮按服务端返回的 allowed_actions 显示。
- **摘要卡**：提交者与提交方式（网页或 PAT）、来源运行与差异、方案修订、批次、关键时间、执行方式、模型与 Harness、排队原因、心跳与停止原因；已删除的运行或数据集版本以横幅说明。
- **四个独立维度卡**：生命周期、评分覆盖、产物保存、环境清理，不用单一“成功”掩盖产物或清理失败；下方是各状态的试次计数。
- **标签页**：
  - 执行：类似 GitHub Actions，左侧是试次，右侧是选中试次的执行尝试与步骤，每步可展开实时日志（Runner 转发的日志；Harness 的轨迹显示为整理过的文本，原始事件流与 `trajectory.json` 只在产物页），日志框标题行可下载该日志，模型运行的尝试下方可展开它用的安装网络版本；选中试次记在 URL（`?trial=`），刷新或分享链接保持。大日志按尾部分段读取。试次下方不列产物，只有“产物 N 个”跳到产物页并只看这个试次。
  - 结果汇总：带覆盖率的统计与逐任务结果（[06](06-results-scoring.md)）；配置快照：不可变的生效配置。
  - 产物：状态与到期时间，可按试次筛选（`?artifacts_of=<试次>`）；过期或失败的产物给出原因，不显示下载入口。

分数单元格区分有效零分（显示 0）、未评分（缺评分）与执行失败，不把空值显示成 0。Oracle 运行标为测试模式，不进入模型能力比较。

已知限制：重跑只能选“全部”或“未得分任务”，API 支持的显式任务子集没有界面。

## 4. 成组提交与后续操作

批次详情列出成员运行的状态与得分 / 计划；取消批次只停止未结束的运行，已获分结果保留。重跑与修改后运行都创建新运行，原运行不变；修改后运行在新运行详情中链接来源并显示字段差异。

## 5. 个人 PAT 与管理员交互

创建 PAT 时选择 scope、有效期与运行上限；原始值只展示一次，之后只显示前缀、用量与到期。

管理员的凭据分区只显示名称，替换时填写新值，不提供“显示原值”；维护分区区分进程存活、就绪与可受理。

## 6. 待处理事项

“待处理”是工作台上对业务记录的查询，不是独立待办，没有“标记已处理”：源对象状态变化后自动消失。成员看到本人已结束运行中的中断、执行错误（含附件安装失败）、环境清理失败和产物保存失败；管理员看到全团队运行的清理与产物失败，另有未全部准入的数据集版本，以及失败或被中断的导入、首次准备等 Operation（共享恢复除外）。每项标明由提交者还是管理员处理，并链接到来源对象。

## 7. 交互验收

- 网页配置解析与 SDK 得到相同摘要；字段错误定位到具体输入。
- 刷新或断线后能找回操作，提交不会重复受理。
- 0、未评分、执行失败和过期可直接区分，不只依赖颜色。
- 不能执行的动作不显示或说明原因；服务端独立校验权限。
- 到期产物与清理失败在运行详情可见，已评分结果仍能阅读。
- 缓存回收后已准入任务仍可勾选；页面能区分首次准备失败、暂态恢复失败和原内容不可得。

## 8. 比较、集合与快照

比较页、集合页与快照页共用一个比较组件（`components/ComparisonView.tsx`），规则见 [08](08-collections-comparison.md)：

- **条件核对**：相同与不同的维度、不能对齐的原因（数据集或计分规则不同）、警告，以及因删除而搁置的运行。
- **失败剔除**：折叠区显示“已剔除 N 个试次（各类数量）”，展开后逐组勾选，有“剔除外部原因”与“不剔除”两个快捷按钮；说明没剔除的失败算 0 分，运行详情页的汇总不受影响。
- **共同任务 / 全部任务**、**排行榜 / 矩阵**（正好两个维度在变时可用，可交换行列）、**基准**；排行榜可按均分、通过率、有效试次或名称排序，单元格悬停显示计 0 分与剔除的原因。逐任务表可筛选“结果不一致”“都没通过”“只有某个通过”“未参与比较”，点格子跳到该运行的该试次。
- **导出 CSV**：排行榜各行，再逐任务逐运行一行。
- **排版**：宽表在自己的框里横向滚动，单元格不换行，第一列（运行或任务）固定在左侧；排行榜的运行名就是可变维度的值，不再另列各维度；原始证据不可用时写在运行名下面。逐任务表的列标题可换行显示完整名称。
- 集合里能写的身份改设置会保存到集合；只读身份的改动只用于这次查看。快照页只能换摆法和排序，数字不变，原始证据的现状写在运行名下面。
- **加入已有运行**：集合页列出最近不在集合里的运行（`GET /collections/{id}/candidates`），符合规格的可勾选后一次加入，不符合的折叠列出与哪些固定维度不同。运行列表多选后、运行详情页也可“加入集合”。
