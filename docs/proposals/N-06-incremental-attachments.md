# N-06 附件增量发布

状态：已确认 · 优先级：一 · 目标版本：0.4.0 · 2026-10-28 · 相关：[配置与附件](../design/03-configuration-attachments.md)、[集合与比较](../design/08-collections-comparison.md)、[API 与 SDK](../design/10-api-sdk-cli.md)、[网页](../design/11-web-ui.md)、U-50、U-51

附件改为按内容寻址的快照：客户端只上传服务端还没有的文件，每份快照以内容摘要为身份，版本号降为可选标签。修改历史留在作者（多为 Agent）自己的工作目录或 Git 仓库里，Maestro 只收不可变的快照。

方向见 U-50，范围与待定问题由 U-51 确认，可以按本文实施。

## 问题

改附件里的一个脚本，现在要重新打包、上传整个包，还得先改 manifest 里的版本号，否则因“同名同版本内容不同”被拒绝。以后附件主要由 Agent 迭代，常同时试几个方向，而现有附件只有一条按版本号排下去的线。

U-49 曾按“服务端从远程仓库地址 + commit 拉取”设计，代价是服务端要管 SSH 私钥、主机公钥、仓库缓存和后台导入任务，只为省掉一次打包；已由 U-50 放弃。

## 方案

### 1. 快照与身份

- 附件按名称归组；每次发布得到一份**快照**，身份是现有的内容摘要（每个文件的路径、SHA-256 与可执行位）。内容相同即同一份快照，重复发布返回原快照，不报冲突。
- manifest 保留名称、影响声明和兼容信息，去掉版本号。发布时可附一个**标签**（如 `v2`、`try-cache`），在同一附件内唯一，发布后不能改指或删除（“最新”按发布时间看）；不给标签时以短摘要显示。
- 发布时可指明**父快照**，只用来展示来历和比较差异，不限制先后：两份快照可以有同一个父，形成树。
- 运行、重跑、集合与比较都按快照摘要引用，标签只用于显示和选择。

### 2. 增量发布协议

1. 客户端在本地对目录逐文件计算 SHA-256，生成文件清单。
2. 询问服务端清单中缺哪些文件内容。
3. 只上传缺的文件；服务端按 SHA-256 校验后暂存。
4. 提交清单（以及可选的标签、父快照）；服务端确认文件内容齐全，执行现有的路径、manifest、数量与大小检查，通过后发布快照。

提交可安全重试；上传了但一直未被快照引用的文件内容过期后清理。

SDK 提供 `publish(目录)`，Agent 改完直接调用，不需要挑文件或打包。不记录 Git 等外部来源。

网页发布用选择文件夹的方式，在浏览器里算摘要，走同一协议。不再接受 tar / zip 包，手上只有压缩包时先解压。

### 3. 取回、浏览与比较

- **SDK 取回**：`fetch(快照, 目录)` 把快照还原到本地目录，只下载本地缺少或不同的文件。Agent 在别的快照基础上继续改、或换一台机器接手时用它。
- **网页浏览**：快照页显示文件树，可查看文本文件、下载单个文件。
- **差异**：任意两份快照（默认与父快照）按文件列出新增、删除、改动；文本逐行差异以后再做。
- **整包下载**：网页可把一份快照下载为 ZIP，保留路径和可执行位；按需生成，不预先存放。Agent 用 `fetch`。

不提供网页编辑。

### 4. 存储与删除

- 文件内容按 SHA-256 单独存放，多个快照共享相同文件；快照是数据库中的一份文件清单。执行时按清单把文件还原为可重建的目录，执行路径上的三次核对不变。
- 停用、回收站和物理删除按快照进行，规则沿用现有附件规则。能否读取、下载取决于快照状态，不取决于文件内容是否还在：物理删除的快照不能借其他快照共享的文件取回。文件内容不再被任何未物理删除的快照引用时清理。
- 现有附件直接清空，不做迁移：新增一个迁移移除旧附件数据。已有运行记录保留，其引用的附件视同已清除，重跑被拒绝。

### 5. 权限

沿用现有附件权限：成员和 experiment PAT 可以发布；所有登录主体和 read PAT 可以查看、比较、取回和下载；停用与删除按发布者与管理员的现有规则。暂存的文件内容只供上传者自己的后续提交使用。

### 6. 不做

服务端 Git 获取、团队 SSH 私钥、托管 Git 仓库、Git 来源记录、tar / zip 上传、网页编辑、文本逐行差异。

## 验收

1. **增量发布**：改动一个文件后再次发布，只上传这一个文件；未改动时返回原快照；中途断线重试不产生重复快照或半成品。
2. **树状快照**：以同一父快照发布两份不同内容，两者并存、都可被运行选用；同一附件内标签重复被拒绝。
3. **检查不变**：非法路径、链接、缺 manifest、超数量或大小、声明影响评分的附件都被拒绝；提交时缺文件内容明确失败。
4. **取回与下载**：`fetch` 还原的目录与快照逐文件一致（含可执行位），本地已有的文件不重复下载；网页 ZIP 与单文件下载内容一致；read PAT 可取回、不能发布。
5. **差异**：两份快照的新增、删除、改动文件列表正确。
6. **删除**：被多份快照共享的文件，在其中一份物理删除后，其他快照仍可用；物理删除的快照不能查看或下载；无引用的文件内容和过期暂存被清理。
7. **执行与比较**：容器内安装的内容与快照一致；附件 A/B 集合按快照摘要区分；只有标签不同、内容相同的发布是同一份快照。
8. **只收目录**：tar / zip 上传接口已移除。

验证使用全新的隔离 state，不需要模型调用。

## 待定问题

无。U-51 已确认：不保留 tar / zip 上传；做网页整包下载；标签发布后固定；本次只做文件级差异；不记录 Git 来源。

## 实现草图（供开发核对）

以下为可调整的实现安排，不增加正文之外的产品要求。现有依据为 dev 的 1c5f256。

- 存储：`src/maestro/execution/attachments.py` 把按摘要整目录存放改为按 SHA-256 存文件内容，保留 `describe` / `files_digest` 的摘要定义；增加按清单还原目录（可重建）供 Runner 使用，执行侧核对不变。
- 发布：`src/maestro/services/attachments.py` 的检查与发布事务改为接收清单；缺失查询与上传按 SHA-256 去重，暂存内容记录上传者和过期时间。去掉 `_unpack_tar` / `_unpack_zip` 及压缩包上传路由。
- 删除：物理删除快照后按引用清理文件内容，与还原目录、下载协调，避免清理途中被读取。
- 接口与客户端：`src/maestro/api/routes/attachments.py` 与公开模型增加相应资源；`sdk/src/maestro_sdk/client.py` 的 `publish` 改为目录、新增 `fetch`；同步 OpenAPI、生成模型、网页类型与 `test_sdk.py` 登记。
- 网页：文件夹选择与 WebCrypto 计算 SHA-256；快照列表、文件树、差异和下载。
- 比较：`src/maestro/services/configuration.py` 的 `comparison_view` 与运行快照中的附件引用改为快照摘要。
