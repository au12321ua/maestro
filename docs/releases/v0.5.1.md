# Maestro 0.5.1

0.4.0 之后的第一个正式版，包含几批新功能。`v0.5.0` tag 已存在，但它的发布任务因工作流问题失败，没有发布包；内容与 0.5.0 相同，另加下面“修复”中的发布工作流修复，因此以 0.5.1 发布。

## 更新后

- 数据库自动追加迁移 0007～0013，不需要重新做首次准备。
- 已有的 PAT 自动换成新的权限形式：原只读 PAT 没有额外权限，原 experiment PAT 带 `experiment` 权限，继续可用。

## 新功能

- **网页检查与触发更新**：管理员可在管理页检查 GitHub 上的正式版，并发起带排空的更新（先暂停派发、等在途工作结束）。开发预览仍下载包后用 `maestroctl update` 更新。
- **服务版本显示构建名**：管理页“服务版本”显示 `<版本>-<提交号>`，同一版本号的开发预览可以区分。
- **细粒度 PAT 权限**：创建 PAT 时在角色上限内逐项勾选权限；带管理员能力的 PAT 有效期更短。
- **工作流记录**：可挂在集合、运行、附件和数据集版本上，网页可添加、编辑、删除和查看历史；记录有给人读写的 Markdown 文字，引用可以点击跳转。集合可以设置“当前最好”的运行。
- **留出题**：建集合时可以标出留出题，平台记录谁在什么时候读过题面，集合页按版本汇总读取情况。
- **上传数据集**：可在网页或 SDK 上传转换好的 Harbor task 数据集，并管理版本：标签、基于哪个版本、任意两版比较、整版下载。
- **附件与提交评分**：Oracle 运行可以带附件；新增附件类别“待评提交”和执行方式“提交评分”，装好提交后直接跑 verifier，不调模型。
- **只下载交付物**：运行的导出可以只打包交付物。
- **回收站批量操作与 Harness 升级**：回收站可多选或按当前筛选全选，批量恢复或彻底删除，失败项保留原因；Harness 可以从已有版本升级到新的上游版本，旧版本与已有运行不受影响。
- SDK 新增工作流模块 `maestro_sdk.workflows`，skill 补充数据集上传与任务环境的说明。

## 修复

- 发布任务检查附注 tag 前重新取回 tag：`actions/checkout` 会把附注 tag 覆盖成普通引用，导致 0.5.0 的发布在第一步失败。
- SQLite 迁移时保留 PAT 的外键引用。
- Runner 接受显式断开网络的 Compose 服务。
- 交付物路径与 Harbor 保存的 `/logs/artifacts` 一致。
- npm 12 下前端 `npm ci` 失败。
- Oracle 与提交评分的运行页不再显示“加入集合”（集合只接受模型运行）。

## 验证

- 发布提交通过完整源码检查（ruff、全量 pytest、前端构建与检查、文档链接），发布任务在全新环境中安装实际 wheel 并核对服务、SDK 与包内页面。
- 各项功能合入 dev 时按各自范围验证过，部分功能另在本机实例上用 Oracle 与演示执行器走过网页流程。

## 未覆盖

- 本次发布没有另做整体的真实 Docker、Hub 与模型验收。
- 网页一键更新到 0.5.0 是这个功能第一次遇到真实的新正式版，从 0.4.0 升级不能用网页更新（0.4.0 还没有这个功能），请用 `maestroctl update`。
