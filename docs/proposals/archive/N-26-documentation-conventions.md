# N-26 文档结构与单向引用

状态：完成 · 日期：2026-11-01 · 相关：U-64、U-65、[文档导航](../../README.md)

## 问题

代码以文档编号与章节定位设计依据，文档重排会使注释指错位置。交接同时承担当前代码状态、完整验证命令与 CI 发布说明，接手和维护的入口不够集中。提案旧规则要求完成后删除，与保留后续设计取舍的目标不同。

## 方案与取舍

- 文档引用代码，代码注释与测试说明独立写明行为、原因和不变量。普通注释不定位文档或内部记录；决定与提案编号用于文档、提交说明和 PR。
- 去掉没有额外信息的编号尾注，保留有价值的解释；原本只写场景编号的测试说明改成行为描述。API 说明中的内部编号一并清理并同步生成客户端。
- 不采用引用检查器、语义锚点注册表或自定义引用工具。代价是从源码查长篇设计需要按模块名或概念搜索，收益是文档结构不再限制代码注释的维护。
- 把现有架构图与边界说明移到架构入口；验证命令从交接移到开发验证指南，发布操作从协作流程移到发布指南，原入口改为链接。交接保留当前状态、接手步骤、环境陷阱与从源码接入真实执行的步骤。
- 之后完成、取消或被取代的提案归档，新决定附原话或可追溯对话出处；已删除提案和旧来源不回补，冻结材料保留原路径与内容。
