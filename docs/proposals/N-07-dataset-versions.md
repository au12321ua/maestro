# N-07 数据集版本操作

状态：已确认 · 优先级：一 · 2026-10-28 · 相关：[02](../design/02-datasets-preparation.md) 第 3 节、[11](../design/11-web-ui.md) 第 1、2 节、[14](../design/14-decisions.md) U-20、U-30、U-53

## 问题

接口早就支持同一个数据集登记多个版本（DS-07），网页上却有两处不顺手：

- **已有数据集上没有“添加新版本”的入口**。管理员要回到“添加数据集”，重新检索 Hub、找到同一个数据集、再选版本；也没法知道上游是否出了新版本，或者导入时用的标签（如 `latest`）是否已经指向别的内容。
- **新建运行页的“数据集版本”是一个平铺的下拉框**，所有数据集的所有版本排在一起（`ns/name @ ref`），版本一多就难找。

U-30 原定的第三处“在已选的运行配置或方案中切换版本”不做（U-53）：换版本相当于换了实验对象，作者可能改了任务内容、参数含义或参数列表，把任务选择与参数按名字带到新版本是在猜。换版本时照旧清空任务与作者参数，重新选择。

## 方案

### 已有数据集上检查上游更新与添加新版本

只有管理员网页会话可用（U-20），沿用数据集登记时的数据源与凭据。全部复用现有接口（`/dataset-search/versions`、`/dataset-search/version`、`/admin/dataset-imports`），不加后端。

- 数据集卡片加“检查上游更新”：列出上游版本，按 `resolved_digest` 对照本地版本，标出三类：**已导入**、**未导入**（新的修订或标签）、**标签已移动**（本地某版本当初按标签导入，该标签现在指向别的内容）。结果只显示、不保存，不定期自动检查。
- 每个未导入或已移动的条目可“添加为新版本”：先预览（现有的版本预览），并和选定的一个本地版本（默认最近导入的）比较任务清单——按任务键与内容摘要列出新增、删除、内容变化的任务数与名单——再确认导入。标签已移动的条目也可一步导入（U-53），确认对话框写明“同一标签已指向新内容，旧版本保留”，请求带 `accept_changed_content`。导入与首次准备照旧是 Operation，进度显示在卡片上。
- 数据集卡片上另有“添加指定版本”，可直接填标签、修订或 digest，免去检索。

### 新建运行页先选数据集、再选版本

- “数据集版本”拆为两个选择：**数据集**（`namespace/name`）和**版本**。版本选项显示标签或修订、导入日期、可提交任务数 / 总数；没有可提交任务的版本可见但不可选并说明原因。
- 默认选最近导入、且有可提交任务的版本（版本没有可比较的上游顺序，导入时间是唯一一致的依据）。
- 换数据集时版本取该数据集的默认版本；换数据集或换版本都清空已选任务与作者参数（现状不变）。
- 从集合新建时两个选择都锁住（现状不变）。

### 数据集版本的网页地址（并入 N-22 的一项，U-53）

数据集页用 `/datasets?version=<id>` 记住选中的版本，刷新与分享保持；运行详情、集合规格等显示数据集版本的地方链接过去。版本在回收站或已物理删除时，链接仍打开数据集页并说明状态。

### 放弃的做法

- **换版本时按任务名沿用任务选择与参数**（包括方案页的“切换数据集版本”）：见“问题”最后一段（U-53）。
- **自动定期检查上游并进待处理**：要定时访问 Hub 并保存结果，目前管理员手动点一下就够。

## 影响

- 系统说明：02 第 3 节补“在已有数据集上检查上游、添加新版本”；11 第 1 节数据集页（含 `?version=` 地址，删去“数据集版本没有独立地址”的已知限制）、第 2 节新建运行流程。
- 接口、数据结构、部署：不变（只有前端）。
- 验收：13 的网页冒烟用例增加两步选择版本与版本地址的场景。

## 验收

- 同一数据集有两个版本，上游另有一个未导入的修订和一个已移动的标签：“检查上游更新”分别标为已导入、未导入、标签已移动；从卡片添加新版本，预览中的任务差异正确，导入后版本出现在卡片上。
- 版本下拉只列所选数据集的版本，默认是最近导入且可提交的版本；换版本后任务与参数清空。
- 打开 `/datasets?version=<id>` 直接选中该版本；运行详情里的数据集版本链接到这里。
- 成员看不到“检查上游更新”与“添加新版本”入口，直接调接口仍被拒（现有权限）。
