# N-42 回收站批量操作与 Harness 升级

状态：完成（U-102） · 2026-11-12 · 相关：[03 配置与附件](../../design/03-configuration-attachments.md)、[07 产物与导出](../../design/07-artifacts-export.md)、[11 网页](../../design/11-web-ui.md)

## 问题

回收站只能逐项恢复和物理删除；大量条目操作重复。Harness 发布新版本时需要重新填写旧版本的配置，容易遗漏协议或参数定义。

开发起点为 `e94d9c4`。此前已有未提交的回收站多选、确认词及 Harness 排序修改，未留下提案；本提案按用户本次确认的范围补写。

## 方案

- 回收站支持逐项选择、选择已加载条目及当前筛选的全部页，批量恢复或彻底删除。操作前说明数量与对象，物理删除统一输入 `DELETE`；单项和批量采用相同确认规则，API 请求同步更新。
- 批量调用现有单项接口，逐项执行并显示进度；部分失败不撤销已成功项，保留失败项及原因以便重试。恢复时父对象优先；引用保护、权限和删除回执沿用现有行为，不引入自动清空或后台批处理接口。
- 带可安装上游包的 Harness 可从已有版本点击“升级”，保留名称、适配器、协议、参数定义和说明，选择确切的上游版本后通过现有发布表单创建新版本。
- 旧版本、已有方案与运行不自动替换。同名 Harness 按发布时间从新到旧显示；发布仍沿用确切版本、协议、参数和唯一性检查，不调用真实模型自动验收。

## 影响

涉及回收站删除确认请求及生成契约、管理页、中英文文案、Harness 列表顺序及系统说明。无数据库迁移，不改变部署布局。删除确认请求是尚未承诺兼容阶段的接口变更。

## 验收

- 跨页全选仅限当前筛选；加载或操作中不能改变选择范围，切换筛选清空选择。
- 批量恢复、删除逐项执行；部分失败时仍可看到全部失败项与原因，并重试；错误确认词不发删除请求。
- API 拒绝缺失或错误的确认词，正确确认保留既有管理员、引用保护及回执行为。
- 升级表单保留原配置，必须选择确切上游版本；发布失败保留输入；成功后旧版本仍存在，新版本排序在前。
- 前后端、SDK 契约、中英文文案、构建、文档检查通过；浏览器验证覆盖上述操作。不使用真实团队 state 或真实模型。

## 待定问题

无。2026-11-12 对话中，用户对回收站与 Harness 升级两项范围分别回复“按这个范围完成”。

## 结果

已实现筛选范围内跨页选择、批量恢复与物理删除、统一确认词及逐项失败重试；Harness 升级复用已有配置发布独立新版本。已同步 API、生成契约、中英文网页及系统说明。验证范围、固定版本及未覆盖项见实施提交说明。
