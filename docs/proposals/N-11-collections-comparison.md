# N-11 实验集合、对齐比较与分析快照

状态：设计中 · 优先级：二 · 2026-10-27 · 相关：[领域模型](../design/01-domain-model.md)、[评分](../design/06-results-scoring.md)、[权限](../design/09-identity-security.md)、[API](../design/10-api-sdk-cli.md)、[网页](../design/11-web-ui.md)、D-008

## 问题

现在每个运行只有自己的结果汇总（[06](../design/06-results-scoring.md)），跨运行比较要靠人工导出后自己对齐。新增 Codex、Claude Code 等 Harness（N-09）之后，主要用途是在同一数据集上比较不同模型与 Harness，需要平台能把多个运行放在一起、按任务对齐、说明哪些条件不同，并把一次分析的结论固定下来。

已有基础：运行快照冻结了生效配置，`comparison_digest`（`src/maestro/services/configuration.py` 的 `comparison_view`）已经去掉运行身份、凭据、任务子集和调度字段，可直接作为“核心条件是否一致”的依据；重跑按任务展开并记录来源运行（D-008 的前半部分）。

## 方案

### 对象与要求

| 编号 | 要求 |
| --- | --- |
| ANA-01 | 集合只保存运行引用，运行可属于多个集合 |
| ANA-02 | 集合可持续增删引用，显示创建者、用途与修订 |
| ANA-03 | 比较必须声明关注的变化因素并展示其他条件差异 |
| ANA-04 | 按任务身份对齐，缺失、失败、重复次数和来源可见 |
| ANA-05 | 分析快照固定运行清单、设置、结果版本和计算输出 |
| ANA-06 | 系统提供可计算差异，文字结论由人或 Agent 撰写 |

- **实验集合**：创建者可编辑、团队可读；跨批次添加不复制结果或产物。其他成员复制后独立维护；需要共同编辑时再加显式协作者，不在首版做。数据上为 `collections`、`collection_members`（`collection_id + run_id` 唯一）。
- **分析快照**：保存 collection_revision、run_ids、result_revisions、focus_factors、alignment_mode、metric_contract、selected_tasks、aggregation_version、computed_summary 和创建时的证据可用性；数据上为 `analysis_snapshots`、`analysis_snapshot_results`，不跟随集合变化。

### 比较前检查

用户声明关注的变化因素（focus_factors），系统逐字段比较其余条件：

| 目的 | 允许变化 | 应保持一致并核对 |
| --- | --- | --- |
| 模型 / Harness 评估 | 模型、Harness 与其接入配置 | 数据集内容、任务范围、附件、资源、计分 |
| 附件 A/B | 指定附件内容或参数 | 模型、Harness、数据集、其他附件、资源、计分 |
| 稳定性观察 | 运行时间与随机种子等声明因素 | 其他内容与资源配置 |

检查结果分三级：

- **阻止直接汇总**：数据集内容不同、任务无法可靠映射、指标语义或单位不同、评分契约不兼容。
- **允许但警告**：资源差异、重复次数不同、部分任务缺失、观察到模型实际版本不同。
- **预期变化**：属于 focus_factors 的字段，仍显示具体差异。

不支持跨数据集版本映射；相同任务名不足以证明是同一个任务。以后若加显式映射，必须保存映射版本与任务内容差异。

### 对齐与缺失

任务键为 dataset_version_id + task_key。三种视图：

1. 交集：所有选定运行都包含的任务，并显示每侧实际已评分覆盖。
2. 并集：所有涉及任务，缺少的一侧显示 missing_task。
3. 原始运行：保留每次运行原分母与统计，不拼接。

行级状态区分 missing_task、not_started、execution_error、scored、artifact_expired。产物过期不等于没有评分，同一行可以“有分数、无原始日志”。重复试次按 repetition_index 展示，但统计先在任务内聚合，不假设不同模型的第 1 次具有配对随机性；每个任务单元显示计划数、已评分数、均值、标准差与通过率。

### 部分重跑的合成视图（D-008）

在不修改源运行的前提下，把同一来源链的重跑结果合并观察：

1. 用户显式选择同一来源链、comparison_digest 一致的运行，并看到逐字段差异。
2. 按任务选 accepted_at 最新、该任务全部计划重复试次都已评分的运行，整组使用该任务的重复试次；不跨运行挑最高分，也不按单个试次挑选。
3. 较新运行该任务仍部分失败时，保留最近一组完整结果并警告；没有完整结果时用最新部分结果并标记 partial。
4. 每行保存 source_run_id、trial_ids、selection_rule 和选择时间。
5. 明示这是集合中的合成分析，不是一个新的原始运行；可随时切回原始视图。

### 统计与结论

只提供样本量、均值、样本标准差、通过率与差值；指标、任务集合和聚合规则一致时才给直接差值，否则先展示原因。系统不自动断言“显著”“提升”；置信区间、显著性检验、pass@k 不在本提案内。

结论记录为“人工 / Agent 备注”（text、author_user_id、pat_id、created_at、updated_at、revision），与 computed_summary 分开存放，不把文字意见当作平台计算事实。

### 快照与下一轮

快照只从生命周期已终结的运行创建，避免冻结时结果仍在变。创建后运行清单、设置和计算值不再更新；要修改就新建快照并记录 parent_snapshot_id。备注修订带作者，独立于快照内容。

从分析发起下一轮时，选择某个源运行重跑或修改后运行（复用现有接口）。加入集合须显式指定可写的 collection_id；无权限时提示复制集合，不能绕过创建者权限。

### 放弃的做法

- 合成视图按单个试次取最好成绩：会系统性抬高分数。
- 把合成结果写回源运行或生成“新运行”：破坏运行快照与结果的不可变性。
- 按任务名跨版本对齐：同名任务内容可能已变。

## 影响

- 数据结构：新增上述四张表（`src/maestro/db/schema.py` 与迁移）；[01](../design/01-domain-model.md) 增加集合与分析快照对象。
- 接口：`/api/v1/collections`（列表、创建、修改、成员替换）、`/api/v1/comparisons`、`/api/v1/analysis-snapshots`；SDK 增加对应资源。
- 权限（[09](../design/09-identity-security.md) 第 3 节加行）：所有身份可读集合与快照；成员网页与 experiment PAT 可创建 / 修改本人集合并创建快照；read PAT 禁止写；他人集合只能复制，管理员可停用违规集合但不改写内容。
- 网页（[11](../design/11-web-ui.md)）：新增“集合与比较”页（成员、关注因素、任务对齐、条件差异、结论与快照）；“修改后运行”确认时可选加入本人可写集合。

## 验收

- 同任务名、不同版本内容的运行不能直接给出 A/B 总分差。
- 一组运行缺一项任务，交集 / 并集视图都显示实际覆盖及排除范围。
- 部分重跑合成结果逐行可追溯，原运行汇总不变。
- 新运行加入集合后，旧分析快照仍保持原清单和原计算值。
- 原始产物过期后，快照显示历史摘要与证据不可用，不显示虚假的下载入口。

场景（原 13 中的 E2E-OUT-02、E2E-OUT-03）：

- **E2E-OUT-02 对齐与新一轮**。步骤：创建集合加入两个不同批次的运行 → 声明附件为变化因素 → 查看条件差异与任务对齐 → 选择源运行修改后提交并加入集合。预期：非预期的模型 / 资源差异产生警告；不同评分契约阻止直接总分比较；新运行的来源和配置变化可追溯；集合不复制产物。
- **E2E-OUT-03 快照与证据到期**。步骤：保存分析快照 → 集合加入新运行 → 触发原产物到期回收 → 再查快照。预期：快照的运行清单与计算值保持，原证据显示过期；集合可继续变化；不会因文件过期而删除评分或误报原始文件可用。

## 待定问题

- 比较 Codex、Claude Code 等不同 Harness 时，“Harness”作为变化因素需要和 N-09 的 Harness 记录方式一起确定（版本、参数是否单独可选为因素）。
- 集合是否需要共同编辑（协作者）还是只靠复制。
- 快照中 result_revisions 的粒度：按运行还是按试次评分修订（取决于 06 中评分是否会被重算）。
- 被删除（进回收站）的运行在集合与快照中的显示方式。
