# 07 产物存储与导出

导航：[总览](00-overview.md) · 依赖：[评分](06-results-scoring.md)、[权限](09-identity-security.md)、[运维](12-operations.md) · 相关代码：`src/maestro/boundaries/storage.py`、`src/maestro/services/artifacts.py`、`src/maestro/services/exports.py`、`src/maestro/services/maintenance.py`、`src/maestro/services/recycle.py`

## 1. 职责与需求

本模块保存和索引日志、会话、验证证据与输出文件，提供下载、批量导出、到期回收和删除。运行配置、评分和产物索引是业务元数据，不随大文件到期。

| 编号 | 要求 |
| --- | --- |
| ART-01 | 产物明确归属运行、试次和执行尝试 |
| ART-02 | 逐项报告保存状态，保存失败不丢已确认评分 |
| ART-03 | 单项下载与批量导出保留来源、缺失和过期原因 |
| ART-04 | 默认 7 天后回收大文件，保留索引与过期标记 |
| ART-05 | 存储水位、准备缓存和导出包共同受控；部分满足，见第 7 节 |
| ART-06 | 存储通过接口访问，SDK 不访问服务器目录 |

## 2. 内容分类与保留

| 类别 | 保留 |
| --- | --- |
| 业务元数据：快照、准入证明、试次结果、契约、产物索引、审计记录 | 不自动到期 |
| 原始产物：日志、会话、输出、验证报告、Runner 诊断 | 团队策略 `artifact_ttl_days`，默认 7 天 |
| 导出包 | 团队策略 `export_ttl_hours`，默认 24 小时 |
| 半写文件、附件上传与整包下载的临时文件、半建的附件目录 | 启动时清除 |
| 本机镜像仓库中的准备好的镜像（U-17、U-55） | 随最后一个使用它的数据集版本物理删除，`maestroctl registry-gc` 释放空间（[02](02-datasets-preparation.md)、[12](12-operations.md)） |
| 本机 Docker 中的准备好的镜像 | 管理员手动回收，用时从仓库拉回（[02](02-datasets-preparation.md)） |
| 服务日志 | journald，由宿主决定 |

原始产物到期时间取所属试次 execution_terminal_at（运行级产物取运行结束时间）加当时团队策略的保留天数；终结后才到达的文件不重新计时。到期时间在详情与 SDK 中可见，重要证据由用户在到期前导出。

## 3. 存储布局与索引

~~~text
/var/lib/maestro/                 data_dir
  app.db
  artifacts/runs/<run_id>/<attempt_id 或 run>/<逻辑路径摘要>
  attachments/  registry/  work/  exports/<export_id>/
/var/cache/maestro/               cache_dir：任务材料
~~~

具体目录见 [12](12-operations.md)；准备好的镜像是数据，所以镜像仓库的存储放在 data_dir。存储键由平台生成，不是宿主路径；同一尝试的同一逻辑路径对应固定键，实时日志与最终副本写同一个文件。索引（`src/maestro/db/schema.py` 的 artifacts 表）保存逻辑路径、kind、大小、摘要、到期时间、状态和原因，不保存宿主路径；API 只给 artifact_id 与下载入口。

产物来自容器可写的挂载目录（U-16），因此不可信：Runner 归档时不跟随符号链接、只读普通文件，按部署配置的每尝试文件数、单文件与总大小上限复制，超限项列为跳过；执行器拒绝逃出归档目录的路径，核对清单摘要，不一致的文件不保存。

## 4. 写入与对账

写入（`RunSink._store`）：文本先按基本规则脱敏（U-10），二进制原样；存储层写临时文件、fsync、原子改名，消费者看不到半成品；成功后索引为 available，失败为 failed（STORAGE_WRITE_FAILED）且试次产物状态标 failed，不重试、不重跑 Agent。每次尝试的文件在提交结果前写入，但保存失败不影响结果确认。试次与运行另有汇总的 artifact_state；complete 只表示当前保存成功，不代表永久保留。

文件与索引不能在一个事务里提交，启动时对账（`Artifacts.reconcile`）并定期清扫：

- 清除崩溃留下的半写文件。
- 索引 available 而文件缺失：标 unavailable（STORAGE_CONTENT_MISSING）；文件回来且大小（小文件还有摘要）一致时恢复 available，以免一次未挂载存储卷的启动永久丢索引。过半缺失时记错误日志。
- 无索引或索引已过期 / 删除的文件是孤立文件，删除；运行中先写文件后插索引，所以定期清扫只处理一小时前的文件。

## 5. 查询与下载

所有登录主体（含 PAT）都可读取团队共享的产物。下载返回整份文件，或用 offset / length（单次最多 1 MiB）分段读取，日志按此分页，响应头给出摘要与总大小；不支持 HTTP Range，执行中日志靠短轮询。凭据、主密钥、Docker socket 和宿主目录不属于产物，没有通用文件读取入口。

不可读时：pending 返回 409 ARTIFACT_NOT_READY；expired / deleting 返回 410 ARTIFACT_EXPIRED，索引仍可查；已删除返回 410 ARTIFACT_DELETED；failed / unavailable 返回 409 ARTIFACT_UNAVAILABLE 及原因。已打开的读取即使文件随后被回收也能完成。

证据不设审计门（U-10）：日志、阶段详情与产物经基本脱敏后即可查看，运行中也可查看，不因疑似残留而扣留。确认的泄露按凭据轮换处理，管理员可删除对应产物。

## 6. 批量导出

请求给出 run_ids，可选任务键、产物 kind 和是否含文件；受理即创建 Operation，由维护循环构建 ZIP。读 PAT 也可导出；每用户同时进行的导出数、运行数和总大小有上限（团队策略与 `export_max_gb`），磁盘低于受理水位时拒绝。导出只对创建者和管理员网页会话可见。

~~~text
export-<id>/
  manifest.json
  runs/<run_id>/config.json、summary.json、artifacts/<artifact_id>/<文件名>
  runs/<run_id>/tasks/<task_key>/trials/<trial_id>/result.json
  runs/<run_id>/tasks/<task_key>/trials/<trial_id>/artifacts/<artifact_id>/<文件名>
~~~

目录名和文件名由服务端安全化生成，安全化后重名的任务键加稳定后缀。manifest 含 schema 版本、生成时间、服务版本、执行器映射标识、错误策略版本、各运行快照摘要与评分契约、任务目录映射和每个文件的摘要；过期、删除、保存失败或缺失的产物列入 missing（含原因与到期时间），不静默省略，打包时摘要不符记为警告。摘要统计与网页同源（[06](06-results-scoring.md) 第 5 节）。

构建前对所选可用文件加读 pin，最长 60 分钟（`EXPORT_PIN_MINUTES`），超时则导出失败并释放，不能无限阻止回收；已过期的内容不因导出重新可用。构建期间所选运行或文件被物理删除时导出失败；运行被物理删除时含它的导出包一并删除。服务重启时构建中的导出重新开始。导出不含凭据、cookie、PAT、主密钥或数据库密文，计入磁盘占用。

## 7. 回收与水位

维护循环（`src/maestro/services/maintenance.py`）定期回收到期且无读 pin 的产物：先标 deleting，删除文件，再标 expired；崩溃留下的 deleting 由下次完成，deleting 不可下载。全部文件回收后试次 / 运行的 artifact_state 为 expired。过期导出包同样回收。

磁盘水位（`src/maestro/services/disk.py`）测 data_dir 所在文件系统：低于受理阈值拒绝新运行和新导出，低于派发阈值排队运行不再开始。阈值在部署配置（D-011 初值）。停止受理时查询、取消和下载照常，已运行项尽力收尾；不因空间紧张删除未到期证据。

准备缓存回收不撤销准入，下一次已授权运行自动恢复同一内容（[02](02-datasets-preparation.md)）。附件安装层随试次容器清理，不混入共享缓存。

### 已知限制

- 水位不含 cache_dir 与 Docker 镜像所在磁盘。
- 准备缓存没有空间配额或自动回收，只能由管理员手动回收（`POST /admin/preparations/{id}/evict`）。
- 保存失败的产物不重试；到期前没有提醒。

## 8. 手动删除与回收站

用户决定（U-08、U-19）：除主密钥外都可删除，分两步；被删数据集关联的运行记录保留。实现见 `src/maestro/services/recycle.py`。

- **范围**：运行、产物、数据集与版本、附件快照、方案、模型配置、Harness、凭据、账户和 PAT。到期回收是自动机制，与手动删除互不替代。
- **放入回收站**：对象从列表和选择器中消失，不能被新提交引用；已有引用仍能解析并标“已删除”；可恢复。
- **物理删除**：只能在回收站中进行，删除内容和文件，不可恢复。`deletions` 表中的行既是回收站条目也是删除回执（对象、操作者、时间），引用方显示“已物理删除”而非悬空。
- **引用方保留**：运行快照已冻结所需内容，物理删除数据集、配置或附件后运行仍可查看；原配置重跑在受理检查中报告内容已删除。
- **运行**：排队或执行中的运行及其产物不能删除，须先取消或等其结束。
- **团队模型凭据**：有排队或执行中的运行在用时不能删除；紧急时先停用，再取消相关运行。
- **PAT 与账户**：删除后立即失效，会话和 PAT 一并作废，历史运行仍显示原用户名并标“已删除”。不能删除自己或最后一个管理员；有排队或执行中运行的账户不能删除。
- **权限**：成员可把自己的运行放进回收站；产物只由管理员删除；回收站的查看、恢复和物理删除只由管理员操作，不自动清空。
- **数据集版本**：物理删除时一并回收其准备缓存与镜像，仍被未删除版本使用的内容保留。

## 9. 验收

- 批量导出包含成功、未评分、已过期三种试次，manifest 准确标记，目录能映射回原运行。
- 文件保存失败但评分已确认，显示评分可用、产物部分失败，评分不回退。
- 回收与下载、导出同时发生时，读 pin 有界保护且最后释放，无长期孤立文件。
- 保留期满后清理产物，配置、评分、索引、来源与操作记录仍可查询。
- 路径穿越、重复文件名或包外符号链接不能写出实例目录。
- 回收准备缓存后准入及证明仍在，成员与 experiment PAT 可直接提交；恢复与回收竞争不产生 ready 但内容已删除的成果。
