# N-32 留出集与任务可见性

状态：设计中 · 优先级：待定 · 2026-11-04 · 相关：[02](../design/02-datasets-preparation.md)、[07](../design/07-artifacts-export.md)、[08](../design/08-collections-comparison.md)、[09](../design/09-identity-security.md)、U-10、U-31、U-69、U-75、N-28、N-31

本提案只记录矛盾和可选方向，留待讨论（U-75）。

## 问题

改进附件、提示词或任何会根据结果迭代的东西（RSI），都应该留一组验证集：改进者只在开发集上看细节，最后在没看过的题上确认效果。平台现在的设计与此矛盾：

1. **所有任务天然可见。** 团队成员互相信任，数据集、题面和产物对所有成员开放，PAT 也能读（U-10、U-31）。
2. **实际测试会暴露验证集内容。** 在验证集上跑一次，被测 Agent 就会在容器里读到题面，trace、日志和产物都会把它带出来，而这些证据按“证据从宽”对团队开放。
3. **现在只能靠自觉。** 首轮 Mesh2CAD 实验（2026-11-04）从另一个数据集里按固定规则选了两道题作为留出题，没有运行。题目是否会泄露，完全取决于 Agent 是否遵守 skill 和工作区说明。

## 需要先回答的问题

- 要防谁？是防改进 Agent 过拟合（人可以看），还是连团队成员都不能看（例如公开评测结果的可信度，U-31）。
- 留出集要跑几次？只在最后跑一次和反复跑，泄露的程度不同。
- 跑完之后，可以看到什么？只看汇总分数、看逐题分数，还是可以看失败原因。

## 可选方向（未评估）

| 方向 | 做法 | 主要代价 |
| --- | --- | --- |
| A. 只靠约定 | skill 和工作区说明约束 Agent（现状） | 无法核实 |
| B. 按 PAT 限制 | 在 N-29 的细粒度权限上加资源范围：某个 PAT 可以在指定数据集或集合上提交运行、读汇总分数，但不能读题面、试次产物和 trace | 权限多一个维度；网页会话照样能看全部，人仍然会泄露 |
| C. 隐藏数据集 | 只能上传、不能读；运行的题面、trace 与产物同样隐藏，只出分数 | 与“证据从宽”冲突；隐藏运行出了问题很难排查 |
| D. 一次性使用 | 留出集只在冻结最终版本后运行一次，运行后就算“已暴露”，下次换新题 | 需要持续补充新题；平台要记录哪些题已经暴露 |

C 与 N-28 的参考集（答案对所有人保密、只在评测端使用）是相近的需求，可能应该一起设计。
