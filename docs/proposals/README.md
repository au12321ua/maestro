# 提案

导航：[文档入口](../README.md) · [系统说明](../design/README.md) · [决策记录](../design/14-decisions.md)

提案是还没有实现的设计。系统现在的样子写在[系统说明](../design/README.md)里，决定写在[决策记录](../design/14-decisions.md)里，提案只写“要改成什么、为什么”。

## 生命周期

1. **想法**：本页索引中的一行。只有一句话，不必有文件。
2. **设计中**：开始认真讨论时，按下面的模板写成 `N-<编号>-<英文短名>.md`。
3. **已确认**：用户确认范围与待定问题后，才能按它实现（用户的决定同时写进决策记录第 0 节）。
4. **实施中 → 完成**：实现合入 `dev` 的同一个 PR 中，把结论改写进受影响的系统说明，删除提案文件，并把本页中这一行移到“已完成”。实施证据写在提交说明与 PR 描述里。

放弃的提案删除文件，在“不做或暂缓”中留一行原因。提案编号不复用。

## 索引

### 第一优先：收拢现场与明显的体验问题

| 编号 | 提案 | 状态 | 要点 |
| --- | --- | --- | --- |
| N-01 | 独立验证环境与 Compose 辅助服务 | 想法 | 每个任务的主环境本来就可以各不相同，缺的是 `verifier.environment` 与 `main` 以外的 Compose 服务。远端分支 `fix/separate-verifier`（`bfe2885`、`34a1293`，部署现场曾运行其构建）只作参考，按提案重新实现（U-32）。该分支中待确认的规则（辅助服务须声明 CPU 与内存、构建参数只接受带非秘密默认值的写法并冻结、对带辅助服务的任务更严格）和“缓存按整个任务计算、任务间不共享”的限制在设计时重新讨论 |
| N-02 | CD：推送即发布，不自动部署（已定） | 想法 | 推送到 GitHub 或 Gitea 的 `dev` / `master` 后，CI 通过即构建发布包：`dev` 为带提交标识的预发布版本，`master` 的版本 tag 为正式版本；SDK wheel 与第三方许可证清单一并发布。部署仍由管理员执行 `maestroctl update`（U-29）。可参考本机未合入的 `feature/ci-package`（`c45704a`） |

| N-04 | 长任务名不破坏排版 | 想法 | 截断加悬停显示全名、可复制；有共同前缀时省略中间；修正 flex / grid 与表格的宽度约束 |
| N-05 | 产物按层级打包下载（已定） | 想法 | 运行页按 任务 → 试次 → 执行尝试 显示目录树，每层可下载 zip；只对已结束、已取消或已中断的运行提供，点击时生成并流式返回，不预先存放；复用导出的大小上限与脱敏 |
| N-06 | 附件下载与网页预览 | 想法 | 目录树、整包下载、文本预览（有大小上限，`bootstrap.sh` 高亮） |
| N-07 | 数据集版本操作（已定三处都补） | 想法 | (a) 已有数据集上直接“添加新版本 / 检查上游更新”；(b) 已选的运行配置或方案中切换同一数据集的另一个版本；(c) 新建运行页先选数据集再选版本 |

### 第三优先：技术验证与后续

| 编号 | 提案 | 状态 | 要点 |
| --- | --- | --- | --- |
| N-13 | [试次粒度调度](N-13-trial-granularity.md) | 想法 | 先测 Runner 启动开销、单试次接口、10 试次并发的资源占用，再决定是否实施 |
| N-14 | 跨任务共享镜像 | 想法 | 按单个镜像内容做缓存键并引用计数，只合并内容完全相同的镜像，不做 Dockerfile 语义比对。存储暂时不是瓶颈，排在 N-01 之后 |
| N-15 | Docker 开销 | 想法 | 每试次的容器、网络、出口控制 sidecar 开销以后会成为瓶颈；先测量各部分占比，再考虑同运行内复用容器或远程执行环境（后者涉及自托管定位） |
| N-22 | 已知遗留 | 想法 | 共享构建不计入主机 CPU / 内存；10 试次并行压测未做；数据集版本没有独立网页地址；“停用但仍在使用的对象”未进待处理 |

### 产品方向：开源的自托管平台与公开评测结果（U-31）

| 编号 | 提案 | 状态 | 要点 |
| --- | --- | --- | --- |
| N-16 | 开源许可证 Apache 2.0（已定） | 想法 | 补 `LICENSE` 与 `NOTICE`，在各 `pyproject.toml` 与前端 `package.json` 写明许可证；发布包附第三方许可证清单。2026-10-27 核对：提交全部来自同一作者；服务、Runner（92 个包，Harbor 为 Apache-2.0、litellm 为 MIT）与前端运行时依赖中没有 GPL / AGPL / LGPL，少数 MPL-2.0 依赖（`certifi`、`pathspec`、`tqdm`，以及只用于构建的 `lightningcss`）不构成冲突。发布前对当时的锁文件重新核对 |
| N-17 | 兼容承诺的起点 | 想法 | 0.x 期间仍可不兼容，但数据库变更从 0.3.0 起只追加迁移（已定，U-34），发布说明列出破坏性变更。自第一个面向外部用户的版本起：数据库自动迁移、公开 API 与 SDK 按语义化版本管理、配置文件带版本号。Runner 协议与内部表结构不在承诺内 |

| N-19 | 外部可安装与可扩展 | 想法 | 能在干净的 Linux 上照文档安装；Harness 做成声明式配置（与 N-09 一起）；数据集来源在 Hub 之外加本地目录与 Git |
| N-20 | 确认项目名 | 想法 | 已有多个知名项目叫 Maestro（移动端 UI 测试工具、Netflix 的工作流编排器），不构成法律冲突但影响检索 |

### 不做或暂缓

- 自动部署（N-02）。
- 多租户 SaaS（U-31）：安全边界建立在成员互相信任上，改为多租户相当于重做产品。
- 改写作者 Dockerfile 换源：只在本机代理与镜像源都无法解决时，作为显式的准备方法选项再讨论，且须计入准备规格。
- 公平调度：2～3 名活跃成员时意义不大。
- [N-21 异机备份恢复](N-21-offhost-restore.md)：暂缓。
- CLI 与 MCP（U-11）、事件流与 webhook：暂不提供。

### 已完成

- N-08 安装网络在管理页配置（合并原 N-10；U-38、U-39）：准备代理、包镜像源等安装变量与 Harness 安装时限放进管理页“安装网络”，按版本保存，准备与执行开始时读当前版本，执行尝试与镜像构建记下版本；`config.toml` 不再有准备代理；管理页只读显示部署配置；`maestroctl check` 报告 Docker 镜像源。结论并入 [12](../design/12-operations.md) 第 3 节等系统说明。
- N-23 现场说明与证据进 Gitea 私有仓库（U-35、U-36）：私有仓库 `auua/maestro-site` 放各主机的现场说明与手动证据，CI 证据用 Actions artifacts；结论并入 `AGENTS.md`、交接与开发流程。
