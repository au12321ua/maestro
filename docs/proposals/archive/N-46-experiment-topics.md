# N-46 实验专题：供人和 Agent 共享的实验视图

状态：完成 · 2026-11-18 · [用户决定 U-110](../../design/14-decisions.md)

实现并入[数据与事务](../../design/01-domain-model.md)、[SDK](../../design/10-api-sdk-cli.md)和[网页](../../design/11-web-ui.md)的系统说明。

## 问题与目标

两位成员采用不同的命名习惯，打开运行列表时，两个实验系列混在一起。一次验证器回归又可能涉及试跑、失败排查、正式比较和几个附件版本，单靠运行名或提交者很难找全。对负责组织实验的 Agent，最费力的是跨会话接手：用户只记得“接着做上次那轮回归”，新会话需要知道实验目的、哪些已经跑过，以及上次为什么停在那里。

**实验专题**让团队给这项工作一个名字和稳定链接。专题保存目的、展示设置和对象引用，按实验问题组织团队已有的运行、集合、数据集与附件。对象可以出现在零个、一个或多个专题中。专题的意义在组织与交接，实验身份、执行配置、权限、比较条件和产物保留仍由对应对象决定。受评容器里的 Agent 只接触原有实验输入，专题提供给在平台外通过 SDK 组织实验的 Agent。

## 专题展示什么

| 内容 | 如何进入视图 | 打开后能回答的问题 |
| --- | --- | --- |
| 团队主动选入的运行、集合、数据集和附件 | 人或 Agent 显式加入，可批量整理历史对象。第一次运行前就可选入计划使用的材料 | 这轮实验打算研究什么，团队挑了哪些证据？ |
| 已选运行实际使用的数据集版本和附件快照 | 由运行快照推导，标明来源运行，与手动选入的材料分别展示 | 当时用的究竟是哪一版？ |
| 集合的成员、比较与结论 | 从已选集合进入原有比较视图。成员运行可按需单独加入专题 | 哪些运行用于同一项比较，按什么条件得出结论？ |

选入公共数据集只添加这一条引用；若据此反向收录全团队用过它的运行，互不相关的实验又会混在一起。移除引用只影响当前专题。专题自身沿用回收站与恢复流程；清除专题时只清理其自身的数据，原对象及其他专题里的引用照常使用。原对象被删除时，入口按其实际状态提示。专题可见性也不能赋予读取或修改原对象的额外权限。[集合与比较](../../design/08-collections-comparison.md) · [回收站语义](../../design/07-artifacts-export.md)

## Agent 从同一个链接接手

1. **找到并打开。** 网页和 SDK 使用同一个专题链接，SDK 也接受稳定 ID。按名称检索返回候选及其目的、ID，重命名后旧链接仍可用。一次概览返回目的、最近一条交接记录（如有）、活动运行数、有限条目的活动与近期运行及其 ID、状态和评分覆盖情况，以及已选集合、材料与实际版本的入口。明细按类型、运行状态等条件分页；只有 Agent 决定调查某个试次时才读日志。专题即使积累数百条运行，接手也只需先读一小份结构化数据。
2. **显式选择提交去向。** SDK 可提供绑定专题的对象，例如 `topic = client.topics.open(url)`，随后 `topic.runs.submit(...)`。命名是接口示意。服务端在同一事务中受理运行并写入专题引用，重试沿用原幂等键。专题已失效时明确报错，避免受理后找不到运行。批次全有或全无，重跑与修改后运行可同样指定专题。会话可以持有两个专题，账号或客户端没有会串到另一实验的全局写入目标。普通 SDK 调用仍可独立提交，同一运行之后也能加入其他专题。[现有提交语义](../../design/04-plans-submission.md)
3. **留下判断。** 扩展已有工作流记录的目标类型，使人和 Agent 都能在专题上写交接，引用已有运行、集合或具体证据。运行状态与分数从原对象读取。交接只需说明事实解释不了的内容，例如“候选 B 的两次验证都超时，先看这两个试次的日志，再决定是否补跑”。已有候选判断和比较结论可以直接引用。专题概览给出最新交接及作者、时间，接手者可查过往记录。[工作流记录与 Agent 工作区](../../design/10-api-sdk-cli.md)

## 人在各页浏览和整理

专题主页给出与 SDK 同源的概览。在运行、集合、数据集和附件页共用专题切换器，各页在选中范围内搜索、筛选和翻页，也可切回“全部”。网页按用户记住浏览范围；同事能同时浏览其他专题。从专题内发起运行时，表单显示默认勾选的“提交后加入本专题”，提交前可以改。旧对象可多选后加入或移出，无须改名或先完成全库整理。

数据集目录按数据集列行，选中后再展开版本与任务，搜索和翻页覆盖所选范围，不把所有版本一直堆在左栏。试次从其运行进入，按任务名或失败状态定位；版本和附件快照也沿用原有层级。通用标签、按规则自动收录和实验方案的引导可待相应需求另行设计。

## 实施影响与验收

新增专题及其引用的持久化数据、概览与分页查询，扩展提交事务和工作流记录的目标类型。实现须同步公开 API、SDK、网页与随 SDK 发布的 Agent skill，提供“从链接接手并交给下一位”的示例。专题不进入配置摘要或比较维度，现有对象无需补填归属。[数据与事务](../../design/01-domain-model.md) · [网页](../../design/11-web-ui.md) · [Agent 使用入口](../../../skills/maestro-sdk/SKILL.md)

1. **换会话接手。** 第一个 Agent 在专题中提交两次运行、记录一条附证据引用的未决问题。给无聊天历史的第二个 Agent 同一链接，它能找出尚在运行的任务、核对原附件快照、读到上次停下的理由，并把一次确有必要的后续运行加入原专题。网页从该链接看到同一批事实。
2. **并行与断线。** 同账号的两个脚本分别在不同专题提交，结果各在指定专题。模拟受理后丢失响应，用原幂等键重试，只有一条运行、一条引用；批次中有成员被拒时不留下部分运行或专题引用。普通提交和老运行可事后批量加入。
3. **核对范围。** 一条运行同时加入两个专题，移出其中一个或删除该专题后，另一个专题、原运行和集合比较仍可使用。选入公共数据集不会引入无关运行；后来发布新附件快照，专题中标为“实际使用”的仍是原版本。专题操作不延长文件到期时间，保留证据需使用[手动保留产物](N-45-auto-concurrency-artifact-retention.md)。
4. **大目录下定位。** 准备跨页的运行和数据集，网页在专题内找到末页对象，进入版本、失败试次再返回时保留浏览范围；SDK 先读有限大小的概览，再分页取回匹配记录，概览本身不读取题面、轨迹或日志。
