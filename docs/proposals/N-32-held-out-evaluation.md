# N-32 留出集与任务清单（task set）

状态：设计中 · 优先级：待定 · 2026-11-04 · 相关：[02](../design/02-datasets-preparation.md)、[04](../design/04-plans-submission.md)、[07](../design/07-artifacts-export.md)、[08](../design/08-collections-comparison.md)、[09](../design/09-identity-security.md) 第 4 节、U-10、U-47、U-59、U-60、U-75、U-78、N-28、N-31

本提案定方向，细节留待讨论（U-78）。

## 问题

改进附件、提示词或任何会根据结果迭代的东西（RSI），都应该留一组验证集：改进者只在开发集上看细节，最后在没看过的题上确认效果。平台现在的设计与此矛盾：

1. **所有任务天然可见。** 团队成员互相信任，数据集、题面和产物对所有成员开放，PAT 也能读（U-10、U-31）。
2. **实际测试会暴露验证集内容。** 在验证集上跑一次，被测 Agent 就会在容器里读到题面，trace、日志和产物都会把它带出来，而这些证据按“证据从宽”对团队开放。
3. **现在只能靠自觉。** 首轮 Mesh2CAD 实验（2026-11-04）手写了一份清单，固定 smoke 的两道开发题，并从另一个数据集按固定规则选出两道留出题。题目是否泄露，完全取决于 Agent 是否遵守 skill 和工作区说明。

## 思路：记下发生了什么，而不是拦截

留出集首先是实验有效性问题，不是保密问题。机器学习里的测试集通常不加密，靠的是约定，以及事后能说清楚调参时没有碰过。所以平台不必把题藏起来，只需要能回答：这些题被谁、在什么时候读过，在上面跑过几次。

平台只记事实，“读过算不算用掉了”“用掉以后怎么办”在写结论时判断（U-59）：由工作流的 skill 建议怎么报告（N-31），由写结论的人或 Agent 说明。平台不为此另设拦截或审计门，“证据从宽”不变。

## 方向

### 1. task set：在数据集之上的任务清单

task set 是一份题目清单，可以来自不同的数据集。它是和集合同一级的管理单元：

- **不是执行对象**：不复制题目内容，自己不执行，不改变运行、比较和计分的语义。
- **成员固定到版本**：每个成员是“数据集版本 + 题目”，并带上 `spec_digest`。同名的题在不同版本里内容可能不同，所以不按名字对应。
- **建好后不能改**：要改就复制成一个新的，与集合规格的做法相同（U-47）。这样“这批题被读过几次”始终指向同一个对象。
- **用途**：开发集、留出集、日常 smoke 清单都是 task set；首轮实验手写的那份清单，就是一个跨两个数据集的 task set。

在 task set 上提交时，按数据集版本拆成多个运行，用现有的批量提交一次受理。汇总按数据集分组；数据集内容和计分规则都相同的才合并，否则各自报告，与现有的比较规则一致（[08](../design/08-collections-comparison.md) 第 2 节）。

### 2. 读取记录落在题目上

同一道题可以从 task set、数据集页面、运行详情或 SDK 读到。只在 task set 的入口记录，绕一下就漏了，所以读取记录落在题目上，task set 只负责汇总成员的记录。

- 记录读了什么（题面、试次产物、trace、日志）、谁、通过网页会话还是哪个 PAT、什么时间。
- task set 汇总成员的记录，比如“冻结之后，谁读过哪些成员”。
- 在 task set 上跑过几次，从运行记录里就能查到，不另记。
- 现有的审计只记写操作（[09](../design/09-identity-security.md) 第 4 节）。读取记录是新增的，数量会比写操作多得多，要单独考虑保留期与存储量。

### 3. 与 N-28、N-31 的关系

- N-28 把一个数据集拆成题目内容、参考答案和评测方案三个组成部分，管的是一道题由哪几部分组成；task set 管的是挑哪些题。答案对所有人保密是 N-28 的问题，不在本提案。
- N-31 的附件改进记录可以引用开发集和留出集的 task set，报告时附上留出集的读取汇总与评估次数。

## 暂不采用的做法

| 做法 | 原因 |
| --- | --- |
| 只靠约定（现状） | 无法核对 |
| 按 PAT 限制读取 | 只拦得住 Agent，人照样能看；先有记录，确实需要时再在记录上加限制 |
| 隐藏数据集：只能上传、不能读 | 题面会经 trace 带出，trace 也得隐藏，与“证据从宽”冲突；答案保密归 N-28 |
| 访问记录挂在集合上 | 集合固定的是配置维度，同一个留出集会被多个集合、多条改进线共用 |

## 待定问题

1. task set 的中文名。要避免与 N-28 的组成部分混淆。
2. 哪些读取算“读过”：汇总分数、逐题分数、失败原因码算不算？列表页上显示题名算不算？
3. 读取记录的保留期与存储量。
4. 集合能不能引用 task set 作为固定任务列表，补上 U-60 暂缓的那一项。集合要求数据集固定（U-47），跨数据集的 task set 怎样与集合配合。
5. 成员所在的数据集版本被删除（进回收站或物理删除）后，task set 怎样显示这些成员。
6. 网页上的入口：建 task set、在上面提交、查看读取汇总。
