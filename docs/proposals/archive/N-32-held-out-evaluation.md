# N-32 留出集与任务清单

状态：被取代（U-85） · 优先级：先于 N-31 的平台部分实施（U-79） · 2026-11-04 · 相关：[02](../../design/02-datasets-preparation.md)、[04](../../design/04-plans-submission.md)、[07](../../design/07-artifacts-export.md)、[08](../../design/08-collections-comparison.md)、[09](../../design/09-identity-security.md) 第 4、6 节、U-10、U-47、U-53、U-59、U-60、U-75、U-78～U-81、N-28、N-31

方向与各项取舍已定（U-78～U-80）。动工前还要和 N-28 一起把数据模型想清楚，见“与 N-28 一起定的接缝”（U-80）。机制牵涉面大、还没想清楚，讨论暂停在这里（U-81），续谈从“讨论现状”开始。

## 问题

改进附件、提示词或任何会根据结果迭代的东西（RSI），都应该留一组验证集：改进者只在开发集上看细节，最后在没看过的题上确认效果。平台现在的设计与此矛盾：

1. **所有任务天然可见。** 团队成员互相信任，数据集、题面和产物对所有成员开放，PAT 也能读，包括参考解与验证代码（U-10、U-31，[09](../../design/09-identity-security.md) 第 6 节）。
2. **实际测试会暴露验证集内容。** 在验证集上跑一次，被测 Agent 就会在容器里读到题面，trace、日志和产物都会把它带出来，而这些证据按“证据从宽”对团队开放。
3. **现在只能靠自觉。** 首轮 Mesh2CAD 实验（2026-11-04）手写了一份清单，固定 smoke 的两道开发题，并从另一个数据集按固定规则选出两道留出题。题目是否泄露，完全取决于 Agent 是否遵守 skill 和工作区说明。

## 思路：记下发生了什么，而不是拦截

留出集首先是实验有效性问题，不是保密问题。机器学习里的测试集通常不加密，靠的是约定，以及事后能说清楚调参时没有碰过。所以平台不必把题藏起来，只需要能回答：这些题被谁、在什么时候读过，在上面跑过几次。

平台只记事实，“读过算不算用掉了”“用掉以后怎么办”在写结论时判断（U-59）：由工作流的 skill 建议怎么报告（N-31），由写结论的人或 Agent 说明。平台不为此另设拦截或审计门，“证据从宽”不变。

## 方向

### 1. 任务清单

任务清单（英文 `task set`，接口与代码用 `task_set`）是一份题目清单，可以来自不同的数据集。它是和集合同一级的管理单元：

- **不是执行对象**：不复制题目内容，自己不执行，不改变运行、比较和计分的语义。
- **成员固定到版本**：每个成员是“数据集版本 + 题目”，并带上 `spec_digest`。同名的题在不同版本里内容可能不同，所以不按名字对应。
- **建好后不能改**：要改就复制成一个新的（复制时可增删成员），与集合规格的做法相同（U-47）。这样“这批题被读过几次”始终指向同一个对象。
- **用途**：开发集、留出集、日常 smoke 清单都是任务清单；首轮实验手写的那份清单，就是一个跨两个数据集的任务清单。

在任务清单上提交时，按数据集版本拆成多个运行，用现有的批量提交一次受理。汇总按数据集分组；数据集内容和计分规则都相同的才合并，否则各自报告，与现有的比较规则一致（[08](../../design/08-collections-comparison.md) 第 2 节）。

### 2. 集合对应一个固定的任务清单（U-79、U-80）

集合建立时绑定一个任务清单，补上 U-60 暂缓的“集合的固定任务列表”。清单可以跨数据集：集合不再固定“数据集”这一维度，题目由清单决定（部分取代 U-47 中“数据集不能设为可变”）。

- 从集合提交一种配置时，按清单涉及的数据集版本拆成一组运行，一次受理；加入集合的运行，任务必须与清单在该数据集版本上的成员一致。
- 比较按“计分分组”分开列出：现在是数据集内容加计分规则，同组的运行照常对齐、给差值；不同组之间只并排，不合并、不给差值（[08](../../design/08-collections-comparison.md) 第 2 节的规则不变，只是同一个集合里可以有多组）。
- 现有集合按基准运行的任务生成任务清单。

清单不可改带来的情况，都按“复制”处理，与 U-53“换版本相当于换了实验对象”一致：

| 情况 | 处理 |
| --- | --- |
| 数据集出了新版本 | 题目内容可能变了，复制成新清单、新集合；旧集合与它的结果不变 |
| 想加题提高样本量 | 复制成新清单与新集合；带过去的旧运行在新题上没有结果，比较照常标为不完整 |
| 成员不可用（第 4 节） | 原清单与集合不能再提交，复制时去掉缺失的成员 |
| 建错了 | 复制或删除，删除进回收站 |

### 3. 读取记录落在题目上

同一道题可以从任务清单、数据集页面、运行详情或 SDK 读到。只在任务清单的入口记录，绕一下就漏了，所以读取记录落在题目上，清单只负责汇总成员的记录。

- **只有能看到任务内容的读取才算**（U-79）：题面、参考解与验证代码、跑这道题的试次产物（含 trace 与日志，它们会带出题面），包括打包下载与导出。汇总分数、逐题分数、失败原因码、列表中的题名都不算；“在上面跑过几次”从运行记录查，不另记。
- 记录谁、通过网页会话还是哪个 PAT、读了哪一类、什么时间。
- 清单汇总成员的记录，比如“某个时间点之后，谁读过哪些成员”。
- 现有的审计只记写操作（[09](../../design/09-identity-security.md) 第 4 节），读取记录是新增的。
- 不存逐次的原始事件，只存汇总行（U-80）：每个“题目 × 读取者（账户，及 PAT 或网页会话）× 读取类别”一行，记首次时间、最后时间与次数，永久保留。行数上限是题目数 × 成员数 × 类别数，不设保留期与配置项；“冻结后有没有人读过”看最后时间。

### 4. 成员不可用

成员所在的数据集版本进回收站或被物理删除、题目不再可提交时，成员显示为缺失（missing）并注明原因，清单整体变为不可用：不能再提交，已有运行、比较和读取记录照常可看（U-79）。从回收站恢复后清单恢复可用。

### 5. 网页

任务清单有自己的列表与详情页：从数据集选题或从已有运行的任务新建、复制、在上面提交、查看成员状态与读取汇总。集合页显示它绑定的清单（U-79）。

### 6. 与 N-28、N-31 的关系

- N-28 把一个数据集拆成题目内容、参考答案和评测方案三个组成部分，管的是一道题由哪几部分组成；任务清单管的是挑哪些题。答案对所有人保密是 N-28 的问题，不在本提案。
- N-31 的附件改进记录引用开发集与留出集的任务清单，报告时附上留出集的读取汇总与评估次数。N-31 的平台部分在本提案之后实施（U-79）。

## 与 N-28 一起定的接缝（U-80）

N-28 会把数据集拆成题目内容、参考答案和评测方案，同一份产物还可以换评测方案重新评分。下面几处 N-32 现在按“数据集版本”设计，N-28 之后会变细，动工前要一起定下来：

1. **计分分组**：现在按数据集内容加计分规则分组；N-28 之后改为按评测身份（评测方案版本、参考答案版本与计分规则）分组。比较和集合只认“分组键”，键里有什么由 N-28 决定。
2. **成员的身份**：现在是“数据集版本 + 题目 + `spec_digest`”；题目内容独立成版本后，成员可能改为指向题目内容的版本。
3. **集合选哪种评测**：一道题可以有多种评测方案时，集合要固定每个计分分组用哪一种。
4. **读取类别**：参考答案独立后，“读参考答案”是单独的一类读取。

N-28 自身的输出契约、结果包和评测器等细节不必先定，只需要先定这几处的数据模型。

## 讨论现状（2026-11-04 暂停时）

- 已定：任务清单的定位、成员身份、不可改与复制、集合绑定清单并可跨数据集、按计分分组列出、读取的范围与汇总行、成员缺失时不可用、网页入口（U-78～U-80）。
- 未定：上一节的四处接缝，以及统一的数据模型写在哪里。Agent 的建议是写进 N-28（数据集的组成部分归它管），N-32 引用；内容是对象之间的关系：数据集（题目内容 / 参考答案 / 评测方案）→ 题目 → 任务清单 → 集合 → 运行 → 试次 → 评测记录，以及 N-31 的工作流记录挂在哪些对象上。
- Agent 的另一条建议：N-32 按“分组键”这个抽象实现，现在键里放数据集，N-28 落地时只换键的内容，不必等 N-28 的输出契约、结果包与评测器定下来。用户尚未表态。
- 顺序：先 N-32，再完成 N-31（U-79）。暂停期间不实施 N-32，也不提前做 N-31 的任何部分（U-81）。

## 暂不采用的做法

| 做法 | 原因 |
| --- | --- |
| 只靠约定（现状） | 无法核对 |
| 按 PAT 限制读取 | 只拦得住 Agent，人照样能看；先有记录，确实需要时再在记录上加限制 |
| 隐藏数据集：只能上传、不能读 | 题面会经 trace 带出，trace 也得隐藏，与“证据从宽”冲突；答案保密归 N-28 |
| 访问记录挂在集合上 | 集合固定的是配置维度，同一个留出集会被多个集合、多条改进线共用 |

## 结果

被 [N-33](../N-33-datasets-evaluation-workflows.md) 取代（U-85），未实施。“与 N-28 一起定的接缝”由 N-33 第 3 节的统一数据模型回答（U-82）：分组键是评测身份；在“数据集版本只固定题目内容”之下，成员身份不变；集合固定每个分组用哪种评测；读取参考答案单独成类。其余内容并入 N-33 第 6～8 节，作为它的阶段 2 实施。
