# N-05 产物按层级打包下载

状态：已确认 · 优先级：一 · 2026-10-28 · 相关：[07](../design/07-artifacts-export.md) 第 5、6 节、[11](../design/11-web-ui.md) 第 3 节、[10](../design/10-api-sdk-cli.md)、[14](../design/14-decisions.md) U-30、U-53

## 问题

运行页的产物标签是一张平铺的表，只能逐个下载。想拿一个试次或一次执行尝试的全部文件（Agent 日志、轨迹、验证输出）在本机看，要么一个个点，要么走批量导出：导出要排队构建、整个运行打包、只对创建者可见，还有 24 小时到期，对“我想看看这个试次”太重。

用户已定（U-30）：运行页按 任务 → 试次 → 执行尝试 显示目录树，每层可下载 zip；只对已结束、已取消或已中断的运行提供；点击时生成并流式返回，不预先存放；复用导出的大小上限与脱敏。

## 方案

### 目录树

产物标签改为可折叠的树，取代平铺表：

~~~text
运行级文件（若有）
<任务键>                                   [zip]
  #<重复序号> 试次                          [zip]
    尝试 <attempt_index>                    [zip]
      agent/…、verifier/…  按 relative_path 的目录展开，叶子是文件
~~~

- 叶子行保留现在表格的信息：类型、大小、状态、到期时间，可单个下载；过期或失败的文件给出原因、不给下载入口（现状不变）。每个目录节点显示文件数与总大小。
- `?artifacts_of=<试次>` 继续有效：展开并定位到该试次（执行页“产物 N 个”的跳转不变）。
- 管理员删除单个产物的入口留在叶子行。
- 长任务键沿用共同前缀省略的规则（U-45）。

### 打包下载

一个接口覆盖各层，按给出的最窄范围打包：

~~~text
GET /api/v1/runs/{run_id}/artifacts/archive
    ?task_key=…   整个任务
    ?trial_id=…   一个试次
    ?attempt_id=… 一次执行尝试
    （都不给：整个运行，含运行级文件）
~~~

- **前提**：运行处于终态（finished / cancelled / interrupted），否则 409 `RUN_ACTIVE`（与运行中不能删除产物同一个错误码）。树根“整个运行”也提供（U-53）。
- **生成**：受理时在数据库里选出范围内的产物，先检查可下载文件的总大小不超过 `export_max_gb`（超了 413 `ARCHIVE_TOO_LARGE`，提示改用更窄的一层或批量导出），然后边读边写 zip 流式返回（`zipfile` 写入不可回退的流，ZIP64，Deflate）。不写临时文件，不建 Operation，不计入导出的每用户数量。没有 `Content-Length`。
- **内容**：只有产物文件和末尾一个 `manifest.json`。zip 内路径用人能读的名字：`<运行名>-<运行短 ID>/<任务键>/trial-<重复序号>/attempt-<序号>/<relative_path>`，各段按导出的 `safe_name` 规则安全化，安全化后重名加稳定后缀。`manifest.json` 列出范围、生成时间、服务版本、每个文件的原 `artifact_id` 与摘要，以及没有打进包的文件（过期、删除、保存失败、缺失、打包途中被回收）和原因——与导出的 missing 同义，不静默省略。配置快照、结果与汇总不放进来，那些属于批量导出。
- **脱敏**：文本产物在写入时已经按基本规则脱敏（07 第 4 节），打包只复制已存的文件，不再处理，与批量导出一致。
- **一致性**：不加读 pin。终态运行的文件只会因到期回收或管理员删除而消失，打包途中遇到这种情况时跳过该文件并记进 `manifest.json`，而不是中断整个响应。读到一半的文件已打开，回收不影响它（与单文件下载相同）。
- **权限**：与单个产物下载相同，所有登录主体（含读 PAT）可用。
- **SDK**：加 `client.download_artifacts(run_id, path, *, task_key=None, trial_id=None, attempt_id=None)`，写到给定文件；登记到 `test_sdk.py`。

### 放弃的做法

- **先写完整的临时 zip 再发**（附件整包下载的做法）：能给出 `Content-Length` 并在缺文件时整体失败，但大运行要先等几分钟、还要占同样大小的磁盘，和“不预先存放”的决定相抵。附件快照小且内容不会被回收，所以那边保留现做法。
- **复用批量导出**：异步、带到期和每用户上限、只对创建者可见，适合归档而不适合即点即看。两者并存：树上下载用于查看，批量导出用于留存与跨运行。
- **按尝试内的子目录打包**（如只要 `verifier/`）：先不做（U-53），需要时加 `prefix` 参数即可，不改设计。
- **运行未结束时提前下载已结束的试次**：不做（U-53），运行中仍可逐个下载。

## 影响

- 系统说明：07 第 5 节加“按层级打包下载”；11 第 3 节“产物”标签改为目录树；10 加接口与 SDK 方法。
- 接口：新增上面一个 GET；`Artifact` 模型不变（树由前端按 `trial_id`、`attempt_id`、`relative_path` 组装，试次与尝试信息已有接口提供）。新增错误码 `ARCHIVE_TOO_LARGE`。
- 数据结构与部署：不变，无迁移、无新配置项。

## 验收

- 已结束运行：任务、试次、尝试与整个运行四层的 zip 各下载一次，解压后的文件与单个下载的内容摘要一致，`manifest.json` 列出的文件与范围一致。
- 含过期、保存失败与被管理员删除的产物：zip 里没有它们，`manifest.json` 带原因；其余文件照常。
- 未结束的运行：树照常显示、单文件可下，打包按钮不显示，接口返回 409。
- 超过上限返回 413，不开始传输。
- 恶意的 `relative_path`（`..`、绝对路径、重名）在 zip 里被安全化，不出现逃出顶层目录的条目。
- 读 PAT 用 SDK 下载成功；网页冒烟用例在手机宽度下检查树没有横向滚动条。
